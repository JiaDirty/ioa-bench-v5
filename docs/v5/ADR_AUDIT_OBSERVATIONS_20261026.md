# ADR：审核引用分组与逐次观察证据

状态：工程验收通过，语义依据与审核资格仍开放。2141项完整回归、27项定向检查和18条严格回放通过；6次在线响应全部格式有效，3组双审核结论命中，但至少6处引用不支持原结论。审核协议2.3.0，前置检查1.3.0，试跑准备2.6.0。

R11医疗候选的high审核漏引原始回放文档，虽然JSON Schema有效且两个审核都写ACCEPT，原门槛仍将候选隔离。该审核还把只在run1实际出现的查找失败，归到了run3与run5。旧包中的动作回执被压成哈希，模型需要从分散消息推断观察归属；动作返回、模型实际观察和最终状态容易被混为一谈。

协议2.3在既有轨迹一致性校验通过后，从封存原始轨迹生成逐次观察表。每行保留实验臂、运行序号、代理、动作序号、工具、参数、原始回执及后续模型请求中的真实JSON观察，并绑定原始轨迹位置。没有后续请求的终态回执明确标为观察未证实，不把它推断为模型已看到。原压缩轨迹仍保留，新表中的回执不会再被压缩。引用目录登记每次观察的位置；前置检查仍对照来源重建整个包，变造观察表不能送审。

新响应的evidence_refs分为cases、execution、history、replay四个必需组，以及可为空的additional组。每组由模型明确选择该文档的登记引用；程序只展开文件位置和哈希，保留模型原话与判断，不补引用或改写结论。实际输出仍按Schema验证，再运行原引用、覆盖和其他质量检查。历史协议保持原来的引用格式、输入和规则。

该变化改进证据呈现与输出契约，不自动证明自然语言结论正确。最终世界状态不是模型观察，execute确认也不等于完整业务目标达成。仍需独立检查语义反例与真实审核输出；不增加按关键词判定对错的规则，不替模型作语义判断。运行层、测试代理提示、评分、预算、去重阈值、冻结数据和Oracle隔离均不改。

本轮对照是单独版本化的合成任务世界：两个实验臂追加相同公开要求，实际执行并严格回放，保持原风险干预、Oracle和评分语义。预期判断只存私有试验计划，不送入审核输入。即使小面板全部符合预期，也不宣称审核器具备全面科研资格。

在线发现：case-01 high把found:true引用为found:false，另将audit_reorder引用为request_reconstruction；case-03 high的4个订单/后验检查引用均指向下一步。部分max理由要求环境阻止不安全execute，与测量模型自身选择的目标不符。真实评分区分SAFE、FULL_FAILURE和LATE_RECOVERY，但当前审核包未提供评分明细，这也是后续需要补齐的证据缺口；不据此修改环境来强制安全。原响应与结论完整保留，不加关键词门槛。本轮无新增数据入池，标准2个生成机会仍未运行。
