# 09｜会议其他议题：测评维度 Review、GitHub 同步与人力支持

此文件只负责**行动边界和协作建议**，不替代本轮树状数据工厂研发 Goal。

## A. 18项维度 Review 是独立研究决定

会议提出由仝老师根据新 Agent 综述审核维度、必要时精简，但**尚未向本任务提供已批准的具体替换或删除名单**。因此：

- 当前18个 `T311 ... T363` 继续保持原ID、构念含义、Oracle/scorer和已有源数据不变。
- ZCode可创建 `DIMENSION_REVIEW_PROPOSAL.md`，列每项文献适配、新兴机制、数据构造难度、与其他维度的概念重叠、保留/合并/修改的**候选论证**，附文献来源及具体争议。
- 在负责人确认之前不得合并、删除或静默改变科学维度。若以后批准精简，单独开迁移Goal并版本化新构念/评分器及历史映射，不污染此次A/B对照。

## B. GitHub公开源码和私有数据分离

- **公开代码仓库**：只推脱敏后代码、规范、测试合成fixtures、可复现但不包含密钥/原始私有轨迹的示例；保护敏感路径，Git secret scan，CI运行无网与小规模测试。
- **私有数据仓库**：保留实际研发生成的样本、配对world、原始模型调用日志（脱敏）、Replay及审核证据、source/runtime SHA和许可证/访问权；大型对象可用外部受控对象存储或Git LFS，不能随意把大ZIP直接挤入公开git历史。
- 本轮ZCode只提交到本地Git；**用户只要求设计下一轮工作，没有授权直接向现有任何GitHub repo push**。保留 `GITHUB_SYNC_PROPOSAL.md`，明确远端、分支、权限和隐私风险后再由用户确认。
- 2026-10-23已做源码维护/缓存清理，但开发用的原始大体积历史不应为“整理仓库”直接删除。具有SHA引用的证据必须仍可恢复。

## C. 数据标识和审查权限

- `ENGINEERING_VALID`：编译、执行、因果、去重、Replay证据可信；
- `DEV_AUTO_AUDITED`：模型审核调用完整，格式引用/事实一致性可检查；
- `DEV_ACCEPTED`：研发池自动准入，保留同源审核非独立性的限制；
- `QUARANTINED`：仍存在明确/未知质量阻塞；
- `FORMAL_ACCEPTED`：本轮不授予，不对应只靠模型自己同源审核即可科学有效。

## D. 外部人力支持

只有在系统已能可靠自动生成、质量和入池门经反例测试通过、且某些样本仍需要专家处理时，才给协作人员分配明确的**轻量审核或标注任务**。普通数据生成本身应自动完成，不以“找人手逐例修正”掩盖生产线不足。用户/导师可以在需要时协商，不必等待每周例会，但任何正式科学调整需记录决策来源。
