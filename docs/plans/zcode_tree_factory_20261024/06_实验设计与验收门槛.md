# 06｜严谨对照、质量门槛、量产前验收

## 一、为什么要对照

过去真实新生成11对、工程通过10对、仅3对新入研发池。现阶段审核负例严格双拒4/6、T321执行不兑现、14项有限语法≤2个单元。不能仅用“新代码更多”“生成样本数多”或“新结构枚举数增加”断言改善。

## 二、测试阶梯（按因果依赖）

| Level | 试验 | 成功证据 |

| L0 | 源码/格式/策略回归 | 旧测试全通过；Schema+硬门负例PASS |
| L1 | 树状分支静态约束 | 行业与上/下游工具/资产/权限/任务联动；非法分支被拒 |

## 三、冻结A/B的分母与执行

研究单元：`(suite_id, target_mechanism_cell, domain_branch, seed, difficulty_intent)`。冻结每个试点T331/T321/T362至少3个任务单元，baseline与treatment均使用相同 **任务分布与历史基线**；如果baseline不支持新IR字段，使用同一风险目标描述与相同随机起点，但明确其 capability mismatch，不能默认baseline与treatment输入完全同构。全部NOT_RUN/失败计入预注册分母，不能在看到成果后删难题。

- baseline：现有四阶段G2+固定Schema；treatment：树分支约束 + MechanismIR + 早期编译/消费见证 + 有界修复。
- 两组相同 `deepseek-v4.1-flash-1017` 网关和已验证 effort；同一类型任务可固定high以剥离模型差异。不同context与output长度若因新架构不同，应报告消耗和可用预算，不刻意强行同文本长度。
- 两组从固定全历史索引开始；每组内部增量去重；交叉方案碰撞另记。不可仅因先跑就占据“新颖名额”，把后跑组天然判重。
- 候选 A/B 比较包含**第一次尝试率**与**允许新ID定向修复后的最终率**两组指标；若只报修复后成功率会掩盖原始可用性。
- 同一新任务机会直到唯一终态（accepted/quarantined/rejected/known provider fail/unknown stop）；若出现全局auth停止，保留完整分母与不同时窗信息，不得以未执行的项目算失败或成功。
- 独立上下文同源 high/max 可作为工程审核，但真实行为判定必须以程序事实和参考执行为底线，审核错/格式错单独计数。

## 四、硬性验收标准

### 可信事实

- schema、契约、执行前置合法，CONTROL/RISK任务、业务世界、权限、工具与基线一致，差异仅风险槽。
- oracle/scorer只能由程序持有；SUT可见素材不能包含控制臂真值、风险标签或安全标准答案。
- 至少原已定义的 strict Replay 个数（当前研发入池≥6行），全部与记录动作/工具结果/终态一致；参考行为、合法任务完成、曝光与风险行动机会必须可复核。
- 全历史 exact/near（历史阈值维持0.9）和结构/行为去重；历史缺损一律 `INDETERMINATE`，严禁“靠版本范围新颖”冒称全历史合格。
- 设计声明的每条**机制性**依赖必须有runtime witness；失败则隔离，不能只凭reviewer接受入池。

### 树状多样性

- 每试点不少于两种由旧基线未覆盖、真实消费的结构候选单元；至少一种跨医疗/金融差异化的完整业务工作流+工具/回执/资源端到端联动。重复不同*领域*不自动计为不同*风险机制*；领域多样性与机制多样性报告两列。
- 匿名节点重命名/行业变更/加形容词/随机seed，结构同构签名不应变化；变更关键条件必须产生预期状态/事件/权力可达性变动。
- 每个T331/T321/T362至少一对新的合格研发数据，合计≥3对；定义“新”必须在本轮新的unique ID和真实发送/编译/历史审核/入池证据上成立，旧对不能凑数。

### AI 审核

- 确定性负例无误入池（旧6+新≥12各至少一次），审核合同里非法 `ACCEPT` 必须`CLAIM_FACT_CONTRADICTION`等错误；统计 double-valid-rejection 与事实硬拒，不混为一项。
- 至少6正例来自不同机制/至少3个套件，每个均有已证实干净的配对/Replay证据；记录误拒和原因，不能靠统一REJECT刷负例通过。若仍有误拒，允许审阅合同优化，但不能通过修改输入标签/原审核判断后称已合格。
- 原始审核JSON、引用sha+pointer、程序验证报告、模型 verdict均保存，摘要报告不能冒充独立科学验证。

## 五、成本和延迟报告

输出每条请求：`model_request_id`, `served_model_id`, `endpoint`, `effort`, `thinking`, `max_tokens`, `input_tokens`, `completion_tokens`, `reasoning_tokens_if_reported`, `finish_reason`, `latency`, `cache_hit/miss`, `cost_estimate_range`, `terminal_class`, `evidence_sha`。缺失usage不当0。若按网页价格估算，则给出来源、日期、峰/谷时间与汇率，不冒充账单。

单位新增合格对成本 = 本轮所有生成+已知失败+定向修复+审核的完整实验费用 / 本轮**新生成且新研发入池**对数。另报干净一遍通过成本、只计模型生成成本、已复用旧样本审核成本。0新对时为`NOT_COMPUTABLE`，不能分摊到原19对降低平均值。

## 六、实验对照的结论口径

- 只有新方案入池更好且有真实新执行结构，才可以说试点取得实质工程进展；小样本3×3不足以支持强统计推广，报告置信区间/描述统计与后续扩样需求。
- 新方案未优于旧方案，也仍需**交失败实验**并修复技术根因；不得降低准入门槛或删掉预注册失败任务。
- `DEV_ACCEPTED` 是研发态，不等于科学真值、实证难度或正式数据冻结；E/M/H仍未经受测Agent实证校准；`T361–T363`维持`SIMULATION_ONLY`。
- Goal 已满足必须有完整G0–G7对应证据。若外部网络、权限、预算触发STOP，则本轮只能 `BLOCKED`，允许保存已完成离线任务，不许虚报整体验收成功。
