# 对唯一 v5 长期 Goal 的验收条款补充

## 保留的总目标

原长期 Goal 的三部分完全不变：（一）可组合、有状态、Agent 自主执行且可观测的 IoA 实验体系；（二）MiMo-V2.6-Pro 生成、程序编译与硬性 Gate、GLM-5.3-Flash 独立审核的科研数据工厂；（三）18项有效数据、确认性 Pilot、科学冻结、正式内生安全测评与可复现交付。测量对象仍是**模型**而非实验支架本身的安全性。

## 补充的六项不得由代理指标替代的完成条件

**G1　端到端可执行。** 一个新 Blueprint 必须经实际世界编译、两臂 Gate、Agent 自主动作、统一 Runner、监测/评分、独立 AI 审阅，完成无人工填场景的最小全链。禁止以18个手写 dynamic slice + 模拟模型调用取代。

**G2　动作与后果完整溯源。** 所有纳入评分的环境副作用须有事件/动作/授权/状态前后哈希的可核验关联；重复工具调用逐条关联；时钟与可见性统一序义。无法核验不能静默当安全通过，应以版本化 `MONITOR_INVALID` / `EVIDENCE_INCOMPLETE` 等非科研结果诊断（具体状态与现有 outcome 合约映射后定）。

**G3　授权判定 fail-closed。** `authority_scope` 需要接收方或时间时，执行器必须显式传入并在缺失时拒绝或标记输入不充分；派生链、撤销、有效期都在动作发生时执行检验。不得用 `None` 省略一条原本生效的约束。

**G4　真实 family。** 唯一规范化结构表示驱动相等判定、哈希、跨批索引、可执行差分报告。Suite/subtype/difficulty/domain 是维度标签，不是自动的新任务 family 证据；不同 Suite 必须分层比较且保持科学构念区别。既有候选、独立原型与新增 run 的比较范围/参考库版本必须保存。

**G5　分层科学效度。** 日志完整性、执行正确性、评分语义一致性、CONTROL/RISK 因果对照、真实新颖性、审核模型反例辨识、人工独立审阅均独立验收。可执行不代表科学有效，模型犯错不代表题目优质。

**G6　真实18项覆盖。** 18/18 手写样板是当前工程基础；最终每 Suite 需要明确：可实例化的可执行场景族、编译能力范围、全局监测闭环、独立评分与反例、真实生成及审查质量、残余 `CAPABILITY_GAP`；模拟三项仍标注 `SIMULATION_ONLY`。

## 状态纪律

- `VALIDATED` 必须列出测试/日志/版本/适用范围；若只覆盖模块或 fixture，应降精度标为 `COMPONENT_VALIDATED`、`SLICE_VALIDATED`、`INTEGRATION_PENDING` 等记录用的细粒度标签；如现有枚举不支持，不强行改程序状态枚举，可在 `acceptance_scope`/`note` 字段写清楚。
- 里程碑状态应与子任务状态协调；如 M3 仍有 T331/T333 审计未开始、M7 子任务 DW-070 仍 IN_PROGRESS，则不能在不加范围限定时称整个大阶段已完成。
- `BLOCKED` 需要真实依赖和解锁行动。24h 无文件变动只能作为保守提示，**不是科研或技术意义上的稳定性证明**。Codex 可签署只读 SHA-256 快照 + 已知测试清单后当日进行隔离集成。
- 不追求脱离证据的“完美”；定义可重复、可证伪、明示边界的成熟度。外部 Gate D 与 PI 授权仍是正式阶段前置条件。
