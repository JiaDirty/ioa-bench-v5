# PI 新决策：灵活模型路由与无人值守工程推进（2026-10-12）

## 1. 覆盖范围与新旧决定的关系

**新的 PI 指示**：不再把数据生成者永久固定为 `mimo-v2.6-pro`、独立审核者永久固定为 `glm-5.3-flash`。工程和数据生产可从 AIHubMix 当前模型目录选择主流、较新、能力匹配的模型，并在故障时选择满足角色资格的备用模型；允许在高难度环节使用更高级的模型。优先保证工程质量、吞吐量和长期任务连续性，API 费用不是实际拦截项。

原 PI-V5-007 及先前 Goal 中的“固定 MiMo/GLM”属于先前实验配置；从本决策生效之后，新建探索性运行可以版本化选择其他模型。**既有运行的模型身份、审核判据、费用、拒收结果、原始日志必须保持原样，不能改写历史**。生成/审核模型路由属于工程与数据来源的版本化变化，必须记录 PI 决策 ID，由 Codex 提议新编号并按项目现有决策簿登记，不伪造批准来源。

## 2. 四类完全不同的模型角色

1. **开发/规划/调试模型**：可快速自由切换，依任务复杂度选择；不是论文测评对象。
2. **场景生成模型**：可在主流厂商之间择优与故障切换，但每条候选应记录具体模型、版本、实际网关、参数、Prompt hash、时间、token usage。可使用多种生成模型，但不能把模型切换混在同一未标注的实验批次。
3. **独立语义审核模型**：对单条候选尽可能与生成模型不同厂商/模型家族；必须在通过所有确定性硬 Gate 之后审核最终可执行 Case，并核对实际证据。不存在独立合格审核者时：等待/转其他工作，不允许生成者自审通过。人工 Gate D 不能被任何 AI 代替。
4. **正式被测模型**：与以上三类隔离。原 v5 正式单模型 DeepSeek 基线不自动替换；可探索其他主流模型，但是正式对照和科研测量**必须先冻结模型 ID、解析后真实 ID、协议、采样参数、候选池、样本集合与评分规则**，不得因某次测评的安全结果自动切换、偷偷混合、事后挑选。要改变已批准的正式目标模型/模型池，单独提出 PI 决策。

## 3. 允许完全自主的工作

Codex 可自主研发、修复、重构受影响的新模块、进行离线回归、可复现校验、模型可用性探针、小规模真实接口验证、数据工厂工程测试、候选蓝图探索与版本化非冻结候选生产，并准备18项数据生产/盲审/复核/确认 Pilot 的全部材料。API 支出不是暂停理由，**但不能无限重试同一种故障，也不能降低科学质量门槛**。

依原 v5 科研契约，以下仍非自动批准：修改18项构念与 GT/Oracle、随被测结果改评分、释放或冻结正式研究数据、宣称 Gate D 人类独立审阅完成、未经单独批准开展确认性 Pilot 或正式 Campaign。遇到外部人类环节，完成审阅包、表单、采样清单、协议、复核辅助工具和前后依赖项，再标记 `BLOCKED_EXTERNAL_REVIEW`；不得停掉无关的工程工作。

## 4. 科学模型分离与公平性

- 生成、审核和被测模型按 `role` 单独记录；同一个模型不得在同一 Candidate 上同时担任生成者和独立审核者。
- 无法知道 `auto` 最终解析模型时，不得把它用于要求模型独立性或正式被测模型固定的环节。
- 独立审核器除了查重，还须检验编译的语义保真、构念一致性、业务合理性和 Gate 缺口；AI PASS 只表示机器复核通过，不是科学冻结。
- 禁止基于最终模型不安全率/受测分数挑选、保留、删改场景；资格判定在正式被测前完成。
