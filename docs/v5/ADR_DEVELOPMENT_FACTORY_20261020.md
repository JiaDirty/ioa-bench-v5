# ADR: DeepSeek 研发工厂与自动审核

状态：2026-10-20 用户明确授权的研发路径；正式科学验收规则不变。

沿用 ModelPort、DeepSeekAdapter、现有四阶段 G2、历史索引、参考执行与严格 Replay。新增 opt-in 研发策略和独立审核请求，不复制模型调用栈。生成和两次审核可以使用同一个官方 deepseek-flash，但请求、上下文、证据绑定分离；研发池使用 DEV_ACCEPTED 等新状态，不能解释成科学独立审核或 MACHINE_ACCEPTED。

审核程序逐项检查 JSON 契约、引用路径与文件哈希，并在入池时从封存源重新投影事实，与审核包比较。硬门失败、历史未知、工具观察矛盾或两审分歧均不能由模型投票覆盖。负例校准原始结果保留，不重刷提高分数。UNKNOWN 全局停止，恢复不重发；完整截断响应单列失败并计入实际 usage。

T362 仅增加有限、类型受限的证据传递图和释放时点，场景版本为 0.4.0，scorer 保持 5.1.0，继续 SIMULATION_ONLY。旧蓝图未指定新字段时保留原行为。T322 未找到120条旧版记录的完整合同，当前候选只能使用明确的 VERSION_SCOPED 范围并隔离，不声称全历史唯一。

取证发现历史 T352 一对数据的动作结果持有可变对象引用，后续状态变化会污染已记录结果。引擎 1.4.4 在 ActionRecord 边界深复制参数与结果，并增加工具结果与后续模型观察一致性检查。旧数据和源码均不改写；受影响对隔离。保留204行响应的重新分析与原源码严格 Replay 分别报告，前者不能替代后者。

本轮还将 T321 naive 参考策略身份版本化为 v2：等待 offer、确认成功建立 session、仅把成功发送计为完成，避免早发错误阻止 CONTROL 完成业务。只修参考策略，保持正式 SUT 提示、评分及旧结果不变。请求意图恢复仅复用唯一且内容相同的前置记录；一旦已有无终态 attempt 仍停止，绝不重发。

T321的 `coverage-T321-01` 保留为 `QUARANTINED`。其gamma/延迟能力设计声明与实际两broker/initial payload不一致，clean-close文字也未成为执行验收条件；不能以元数据FIDELITY或参考策略v2修复替代这些缺口。`deliveries_done` 仅统计broker发布，原high对该计数的Replay推断不成立，但原审核结果和分歧不重写为PASS。后续版本须先对齐可执行声明及明确关闭语义，原scorer与历史分数不改动；本轮绑定取证见 `T321_DESIGN_FIDELITY_LIMITATION.json/md`。

执行与验收证据位于 artifacts/v5/data_factory/dev_auto_audit/round-20261020。源码回归、真实请求分母、研发入池数、结构上限、校准失败、费用估算及未运行项以该目录最终 ROUND_REPORT.md 和 EVIDENCE_INDEX.json 为准。历史32对保留，不重新生成。正式生产、Pilot、Campaign、难度实证校准及科学发布未获本轮执行资格。

入池边界从已封存的 MANIFEST.task、RESULT.task 和调用者范围取最严格值，禁止调用者将 VERSION_SCOPED 提升为 FULL_HISTORY。修复前两项失败、修复后回归和真实 T322 三路隔离证据均保留；42条既存入池记录重算一致，未改封存结果。

首次交接解压验收发现 Git 忽略的六个安装元数据文件仍参与既有权威 runtime 哈希。打包器必须保留这些哈希输入并继续执行脱敏检查，不改变历史哈希算法或移除本机文件凑通过。失败包、最小复现与修复回归单独留存，最终交付使用新版本目录。
