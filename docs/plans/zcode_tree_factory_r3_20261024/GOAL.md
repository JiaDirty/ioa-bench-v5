# GOAL — IoA-Bench v5 R3 可组合业务 DAG 与可证据化生成工厂

**工作区**：`D:\Project\ioa_codex_spec` · **执行器**：ZCode GLM-5.3 Max · **生成/研发审核**：AIHubMix `deepseek-v4.1-flash-1017` · **前置版本**：R2 源码/证据与独立审查（不是盲信 R2 完成声明）。

## A. 唯一主目标

**在不改变18项测评构念、评分真值及 CONTROL/RISK 单点风险干预的前提下，将 R2 的“预先写死三步业务流程 + 模型仅选既定 suite_payload”改为“模型可基于声明能力自主组合新合法业务工作流 DAG，程序端类型检查、编译实际工具/角色/事件/可见证据，并用每个真实执行轨迹闭环验收”的数据工厂；T321 必须从单步变成真实多阶段业务链，T331/T362 用同一可组合机制证明跨测评通用；生产新且历史不重复的 DEV_ACCEPTED 配对数据，并完成经预注册的新旧对照与可复现交接。**

这是 R3 的唯一验收合同。G0～G7 全部要有真实可核证文件和命令结果。不能通过降低门槛、重贴标签或把设计图冒充运行事件来宣布完成。

## B. 硬性成果与非目标

1. **复用优先**：以 R2 `scenario_tree.py`、`business_binding.py`、`mechanism_ir.py`、`compiler_capabilities.py`、`tree_factory.py`、`dynamic/business_tools.py` 及现有 T321/T331/T362 slices 为基础。只在真实消费链需要时扩展，禁止再建并行“第二个工厂/第二套模型 SDK/第二套评分真值”。
2. **可组合能力**：引入版本化、显式工具/权限/证据/前置约束的 `WorkflowPlan` 和最小 `WorkflowModule` 目录；模型必须能提出至少一种**原静态 `BUSINESS_FLOW` 未直接列出**的可执行合法 DAG，程序必须能编译、参考执行与 replay；支持串联与分叉/会合/可选分支中至少两类实际形状；使用确定性入口/出口及事件前置，不以任意 Python 代码生成代替。
3. **T321不改变测评对象**：原测评侧的 `integration_agent` 与协商污染判定维持语义；使用明确的受测 agent 与确定性业务参与者/业务服务角色，或者有授权的单智能体多职能方案，形成**≥3个真实工具/业务阶段 + ≥2个不同逻辑角色 + 至少1次跨角色证据/事件依赖**。至少一组违法顺序/越权测试确实失败；日志不能伪造为多 Agent；对原有 score/oracle 有回归证明。
4. **见证验收**：重写/加强现有 `business_witnesses`，从真实 trace 中按 `run+arm+policy+action.seq/事件id` 关联每个工具调用与后续事件、回执/证据ID、角色可见权限和 stage 完成。测试必须让跨 trace 借事件、伪造收据、缺证据、提前事件和拒绝后仍被计作成功等恶例得到拒绝；不得使用 `len(events)≥len(calls)` 代替对应关系。
5. **真正多样性**：按工作流图同构归一、机制执行签名、样本实例三级报告；行业切换只换名词不得计为新工作流家族。每个试点至少实现并**真实见证两种相对 R1/R2 已封存结构的新工作流家族**；不得把同一拓扑改组织名或节点ID重复计数。已存在的 17 对 R1/R2 数据保持只读，不计 R3 新增。
6. **新合格数据**：T321/T331/T362 各至少 **2 对全新 `DEV_ACCEPTED` CONTROL/RISK 配对样本**，每套至少两种本轮实际执行、经历史去重后的不同可执行工作流家族；合计最低6对。本轮新增仅按全新 ID、真实硬门、严格 Replay 和研发审核全部通过计数。若某类新拓扑无入池表现，不许用旧家族凑数。
7. **实验**：冻结源码、任务/种子/行业/机制难度与模型参数；同一组至少每套 **6个 matched opportunities** 比较 `R2-compatible baseline` 与 `R3 compositional`；每个臂分别记录原始第一次结果、后续修复结果、全部调用次数及失败分类，不得中途改实验条件后仍声称“冻结因果比较”。规模不足只报告探索性，不声称统计显著。做 Tree、Composition/IR、Witness 三组件的明确离线消融/反事实测试，且呈现实际执行区别。
8. **研发审核**：程序先做可确定事实检查，模型专注业务/机制语义审阅；负例、正例与真实误判原始材料都留存。两个同源 high/max 审阅只能称**研发审核**，绝不能称科学独立审核。
9. **工程交付**：现有完整测试回归、严格 Replay、受保护历史范围校验、最终 HEAD 绑定、两个可审查 ZIP、逐文件校验、完整失败分母、可复现命令与 R3 复盘。禁止拿 R2 的1928项历史结果当作 R3 HEAD 的回归。

**明确非目标**：本轮不是一次性为其余15套测评写完全部 runtime，也不是建设任意 Python/任意工具执行系统；不修改18项测评指标、不伪造历史、不过早宣称发表级 Gold 或统计因果优越。
