# 主分支数据生成流程与试跑（2026-10-25）

本轮在main继续改进共享生成链，使用新候选、新请求和新输出目录；R1/R2/R3原始实验与冻结对照保持原样。当前生成器版本为`ioabench.v5.tree-factory/1.2.1`。首批6候选使用1.2.0，后续修正使用独立批次，不将结果混入旧对照。

## 直接修正的数据流

- 规划提示只列当前已选业务义务、角色、工具和证据实际支持的模块，明确拓扑顺序和回执参数与前置事件的对应关系。
- 先生成负载并用原有蓝图校验器核对类型、跨字段约束及冻结覆盖目标，再生成工作流。原有的一次修复机会现在也能处理明确的语义错误，仍使用新请求ID；不增加重试、模型替换或默认答案。
- 1.2.1同时执行编译器原有的fidelity检查（蓝图能否按声明执行的语义检查），并在提示中给出其现有参数约束，覆盖“三家broker配置但省略数量导致实际使用两家”的真实失败。
- 运行时角色和绑定校验都取自实际候选的IR投影，避免静态示例中的节点数量或broker配置污染实际候选。
- 新批次按历史已合格候选的覆盖格子选任务，并将已执行的工作流结构提供给生成器作多样性指导。规划focus仅是任务意图；结构统计另用既有类型图规范化函数计算。
- 每批将研发入池样本写入`DEV_POOL_INDEX.jsonl`。下一批合并R3及`main_quality_*`的已发布索引、按证据路径去重，并把当时的完整池冻结为`HISTORY_POOL.json`；正常续跑继续使用该快照。

## 结论边界

自动入池仅表示同模型研发审核通过，不表示独立科研验证；难度标签仍需校准。业务工作流类型图不同，不自动说明风险机制出现新科学家族，未实际执行的条件分支也不能算执行见证。讨论扭曲保持`SIMULATION_ONLY`。其余15项尚未接入这条可组合业务链；本轮不声称18项均可高质量批产。
