# Codex 夜间可重入执行契约：持续推进而不是假忙

## 一、主工作区写入所有权
- `D:\Project\ioa_codex_spec` 只允许一个活动写入者；Codex 主控前确认 ZCode 已暂停写入，或双方约定互不重叠的文件集/集成窗口。
- 快照/历史实验/旧 2160 候选只读；Codex 的旧 T321 交付快照不可回写。无 Git 元数据时使用版本化目录备份、差异清单、内容哈希，不能假装有 worktree。

## 二、启动即扫描当前状态
优先真实读取 `AGENTS.md`, `state/PROJECT_STATE.yaml`, `state/WORK_QUEUE_V5_DYNAMIC_WORLD.yaml`, `docs/v5/V5_PROGRESS.md`, `docs/v5/V5_PI_DECISION_LOG.md` 和最新 M5 报告，检查当前是否有新的已实现源码或模型测试结果。修复工作队列与实际成果不一致的情况。避免重复实施已完成任务。

## 三、工作调度循环
每一轮选择最高价值的**未完成且可执行**任务：
1. 有阻断性确定性错误优先修复并做正负回归。
2. 当前高价值主线：M5 后续模型路由和真实生成→编译→Gate→动态 Runner/监测/评分→去重→独立审核的贯通证据。
3. 由 T321 → 不同机制 T312/T331/T352 → 其他 Suite 分批推广；每一项先形成一个完全证据闭环，再扩量。T331/T333 审计不跳过。
4. 进入已批准、未冻结的数据扩展阶段后，优先填充分层覆盖和新颖结构缺口，而非追逐通过数量。大规模扩产依已批准的阶段范围执行。
5. 同时准备人类审阅包、审阅标准、盲化样本、冲突仲裁说明及复核界面；为 Gate D 留下可直接执行的待办，但不冒充人工签署。
6. 达到协议中需 PI/真人决策时，记录准确 blocker，转去其他可执行任务，不要停在同一告警上循环。

## 四、心跳和进度证据
在项目现有 `artifacts/v5/overnight_runs/<run_id>/` 下写入：
- `RUN_STATE.json`：当前任务、状态、最后实质进度时间、具体通过/失败测试、代码路径、开放 blockers、选用模型和自动回退记录、外部 API 调用量；原子写入。
- `EXECUTION_LOG.jsonl`：逐轮决策/代码变更/测试/验收证据，支持断点恢复。
- `NEXT_ACTION.md`：任何时刻给新会话可直接接手的一项可执行下一步及相关命令。
- `MORNING_REPORT.md`：人类可读、有证据的晨间总结。
心跳不代表进度；若超过合理时间只有心跳没有测试、代码、数据或诊断证据，标记 `NO_SUBSTANTIVE_PROGRESS` 并调整策略。

## 五、稳定性与故障处理
- 失败分类为 `PROVIDER_UNAVAILABLE`, `API_TRANSIENT`, `SCHEMA_FAILURE`, `CAPABILITY_GAP`, `QUALITY_REJECT`, `TEST_FAILURE`, `SCIENTIFIC_DECISION`, `EXTERNAL_REVIEW`。
- `no_available_channel` 不得导致整夜阻塞：对该模型及时熔断、换同等能力的主流备用模型，记录选择。失败必须追踪 root cause；不能对原本结构重复的案例反复换厂商催生 PASS。
- 连续两次相同确定性构建失败，应暂停昂贵 API 阶段、先修缺陷。对同一固定错误限量重试，失败后把当前任务隔离出来并转下一个高价值任务。
- API 成本无固定上限但禁止无证据、无进度的无限循环；保留真实用量，不能据费用高而盲目用低质模型。
- 任何生产性写入都应具备幂等/append-only 语义、运行 ID、schema version、原始请求响应 hash；定期验证新修改未污染历史数据。

## 六、跨会话真正持续运行
Prompt 不等于进程守护。Codex 如支持可验证的 CLI 非交互模式，才可由**用户已经授权且经本机验证**的启动/调度器反复启动“读取 RUN_STATE→执行一个有限可验收批次→持久化→继续下一轮”。可考虑 Windows 任务计划程序或服务管理器，但必须实际验证 Codex CLI 版本/权限/超时/退出码，不能凭空声称已经配置。通过唯一工作区锁避免两个 Codex 同时写入；重复启动要能幂等恢复。
未配备可重启的本机守护流程时：保持尽可能长的交互会话，持续保存可恢复状态，但明确说明无法保证用户睡眠期间所有时间段都自动工作。切勿悄悄打开危险的全系统自动权限。

## 七、完成/暂停条件
- 真正完成：按原科研和工程 Gate 对所有具备条件的交付物提供原始验证依据；禁止“很多测试通过”替代构念效度或真人审阅。
- 真人审阅暂缺：把其他自主工作做到可交接状态、把人工缺口封装成可执行清单，然后报告 `BLOCKED_EXTERNAL_REVIEW`，不要虚称全部完成。
- 不得因用户没有当场回复、MiMo不可用、单个 Suite 卡住而整体提前结束；找其他可继续任务。
