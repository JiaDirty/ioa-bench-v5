# 03｜ZCode GLM-5.3 多轮执行任务队列（M0–M7）

**模式：** 以 `/goal` 为唯一长任务目标，以 `GOAL_PROGRESS.json` 作为每轮机器可审计进度；每项完成都必须有运行证据。遇测试失败继续改代码，不以“文件已创建”作为完成。不要自行 push 或修改用户未跟踪文件。

## M0｜基线与零付费鉴权前检查

- `git status --short`, `git rev-parse HEAD`；审阅 `AGENTS.md`、`CLAUDE.md`、State/WORK_QUEUE、2026-10-23 `docs/PROJECT_PROGRESS_20261023.md` 与最新 `ROUND_REPORT`；检查有无他人写锁/正在运行的任务。
- 从当前全工作区生成只读保护清单（历史cases、旧运行原请求/响应、原审阅 verdict、数据池、测试原始失败）；不把已有历史报告计为本轮测试。
- 记录所需 `src/ioabench/...` 对象的依赖图/消费者，尤其 `acquisition.staged_proposal`, `bounded_compiler`, `suite_adapter`, `pipeline.compile_and_gate`, `development.admission`, `development_audit.validate_review`。
- 明确新试验目录 `artifacts/v5/tree_factory/<new_run_id>` 与 manifest；任何冻结任务/账本不可覆写。确认`AIHUBMIX_API_KEY`存在**仅布尔状态**，禁止回显值。
- 交付 `BASELINE.json`, `SOURCE_DEPENDENCY_MAP.md`, `PROTECTED_HISTORY_MANIFEST.json`。

## M1｜审阅与设计—执行的 P0 修复（先离线）

1. 在 `development_audit.py` 增加 program-owned `AuditFacts`、`EvidenceSummary` 与 `assertion_evidence_consistency`，逐断言校验程序真值、引用精确含义与 verdict，不准用合规 JSON Pointer 替代证据支持。保留旧审核包/协议版本并引入 v1.2 新版本。
2. 明确且拒收：`UNPAIRED`、多干预、Oracle 泄漏、无因果、历史不确定、无Replay、工具回执污染、声明的结构未被运行时消费。测试包含“真实路径+正确sha+错误结论”负例。
3. 修复或封禁 T321 只保存在 metadata 的图/3 broker/clean close 等设计声明；T352新增实际 SUT 工具观测 ↔ 模拟世界工具回执的逐事件比对。旧坏样本仍隔离。
4. 审核 JSON 格式/协议失效计入 `AUDIT_FORMAT_INVALID`，与语义误判分开。测试至少包含既有6个负例 + 新增 ≥12 个不同类型硬错 + ≥6 个旧/新来源合格正例（只允许证据真实成立）。新增用例不得只从原6题改写词。校准报告分别给出 hard gate 拦截、AI verdict、引用有效、事实一致、错误接受/错误拒绝；不凭重复同题刷6/6。
5. 完成最小受影响 pytest 和逆向失效复现，生成 `P0_AUDIT_AND_WITNESS_REPORT.md`。

## M2｜树状领域规划与约束解析（离线）

- 新增 `scenario_tree.py`（或项目一致命名）：版本化BranchRegistry/WorkflowPackage/Resolver；优先2个**完整**业务包：医药库存、金融清算。每个包包括角色职责、资产 schema、资源生命周期、工具参数/回执、权限、证据来源、数据生产和消费顺序。
- 将 `seed`、coverage target、候选分支与互斥关系绑定；输出 `BRANCH_DECISIONS.json`。**约束传播**在选父分支后限制子域值，阻止“医院药房接银行清算工具”的逻辑混搭。
- 至少三层分支决策和两组反例：业务类型切换导致数据/工具/角色实际差异；互不相容节点静态拒绝。合理的语义变化可以大段不同，但不把仅文本变化算作新结构。
- 核心业务插件不能自己接触 Oracle truth、SUT prompt 或测试结果；工具必须数据驱动/显式 allowlist。
- 交付 `TREE_SPEC.json`, `TREE_SELECTION_RECEIPTS.json`, `test_scenario_tree.py`。

## M3｜MechanismIR与可编译 Capability（离线）

- 优先实现 `mechanism_ir.py`（版本化 schema/类型检查/规范化签名）与 `compiler_capabilities.py`（suite注册、合法因果槽、消费字段、dry-run静态 checker）。允许旧 Blueprint 经显式兼容适配后进入现有编译器；不影响旧样本的 canonical hash。
- T331: 研发试点合法的可执行拓扑 / 传播/确认约束，禁止任意无界图；提供具有运行时动作或事件影响的新组合。T321: broker/证据释放/close 必须真实消费。T362: 在旧证据流结构上复用延迟发布/中继/汇聚，但保留 SIMULATION_ONLY。
- 每个合法 IR 机制生成双臂只一处干预，跑编译+参考执行+oracle安全+行为负控+strict Replay；每条 design assertion 产 `CompilerBinding` 和 `ExecutionWitness`。没有可核event/行为后果，则按 `DESIGN_EXECUTION_FIDELITY_FAIL` 拦截。
- 实验最低要求：3个试点各新建≥2个被执行消费的历史未覆盖结构**候选单元**，新单元单因素负控通过；这个数字用于原型验收，不意味着已获科学新机制家族证据。
- 交付 `IR_SCHEMA.json`, `COMPILER_CAPABILITIES.json`, `ASSERTION_WITNESSES.jsonl`, 反事实测试与严格Replay证明。

## M4｜早期生成与错误驱动修复控制器（先离线，后小额付费）

- 重排 `acquisition.staged_proposal`: 先选择合法业务树及 IR skeleton + 静态检查，再发复杂 `world_graph`/`surface_artifacts` 请求；对 `truth_owner=program` 清晰标识程序所有，不能宣传AI在该阶段创作风险真值。
- 新的有界 `CandidateAttempt` 状态机：`PLANNED → PROPOSED → STATIC_PASSED → COMPILED → REFERENCE_VERIFIED → FIDELITY_VERIFIED → HISTORY_VERIFIED → REPLAY_VERIFIED → AUDITED → DEV_ACCEPTED/QUARANTINED/REJECTED`。任何失败保留证据，不推进后继耗费步骤。
- 对明确终态的 JSON/局部 schema/非法分支选择允许 **最多一次**新请求修复；对能力缺口形成 backlog，绝不暗改 compiler; 对风险图/干预改变必须新候选ID、重跑所有门；不重用不完整 POST/UNKNOWN。
- 生成前可通过覆盖规划器规划新结构，而不是生成后才发现与历史过分相似；`HISTORY_INDETERMINATE`仍拒入。
- 最后开放仅 T331 的新鲜最小在线正例，证明 AIHubMix 完整响应与承载；输入/输出/思考 tokens、usage 和因果证据写终态文件。

## M5｜冻结方案的在线对照试点

- 在任何付费调用前生成 `AB_PREREGISTRATION.json`、`TASK_SET_FROZEN.json`，指定 baseline旧四阶段G2、treatment树状IR+早检查、相同三套件、同样每套件至少3个新任务机会、相同大体难度配额、model/effort/历史基线、语义判断/去重/终态规则。
- 两组都从**干净且隔离的历史起点**计数；两组之间相互重复的结果单独作为交叉重复记录，不能只惩罚后跑的一组；顺序/时段影响需要随机交织或固定块设计，遵守Provider稳定性。严格区分完成率与Provider失败率。
- 接受严格定义：同一双臂baseline、因果、真实 witness、Oracle firewall、参考执行、完整strict replay、全历史确认非重复、事实审核一致、同模型研发审核合法；原来已有的19对绝不算新通过。
- 至少取得每个试点≥1对新 `DEV_ACCEPTED` 且结构为旧历史未覆盖（共≥3对），若无法做到则**本Goal不达成**，报告硬阻塞/源码能力不足而非临时降低门槛。
- 交付 `AB_RESULTS.csv`, `NEW_POOL_INDEX.jsonl`, `COST_AND_YIELD.json`, `FAILURE_FUNNEL.csv`, `STRUCTURE_CELLS.csv`。

## 停止与续行规则

- 硬外部阻塞：401/403、`REQUEST_UNRESOLVED`、密钥权限不足、预算硬限、无法取得保证全历史去重必需的资源——停止新付费调用，但可离线继续M1–M4/M6/M7；在报告中标 `BLOCKED`，不可误报 Goal 成功。
- 修复代码普通错误无需反复询问，及时创建新的证据版本、不覆盖旧文件；同问题连续两次新候选仍失败则分类入 backlog，转下个独立子任务。
- 每完成一个里程碑，更新 `GOAL_PROGRESS.json` 与短中文摘要；尽量使用ZCode的自动目标核验，只有真实产物满足G0–G7才结束。
