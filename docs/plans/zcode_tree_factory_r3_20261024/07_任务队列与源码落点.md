- 读 `AGENTS.md`、最新 `PROJECT_STATE.yaml` 等状态、R2 Goal 与本包；`git status --short; git rev-parse HEAD; git log -5 --oneline`。
- 计算 R2 `a6e6e30` → 用户本地最新 SHA 的变化：会话称 `8e3c704` 仅是参考，不是硬编码目标。若非其后代则记录分支与 merge 基础，绝不强制重置。
- 收集 R1/R2 17对 `DEV_ACCEPTED` 的 frozen IDs、source hashes，核对历史索引与上一轮两项“材料缺失”选测入口。
- 选用新的 `artifacts/v5/data_factory/tree_factory_r3_<runid>/`、单独 request id 前缀；全部旧 STOP/ledger/evidence 只读。
- 输出 `BASELINE_R3.json`/`R2_RECONCILIATION.md`。此阶段无需模型调用，不额外造保护框架。

## M1 · 先修 T321 多阶段 + 最小新模块接口

- **代码**：`src/ioabench/v5/ai_generation/business_binding.py`：移除静默 `steps[:len(agent_ids)]`，改为合法明确的角色映射/业务动作调度；`src/ioabench/v5/dynamic/t321_slice.py`、`dynamic/business_tools.py` 和必要的 engine hook：确定性环境角色具备可核证的 actor/event/receipt；保持原受测 agent 不变。
- **测试**：改/增 `tests/v5/test_tree_ir_runtime_r2.py` 及 `tests/v5/test_t321_business_multistage_r3.py`。先搭3阶段医药/金融直链通过，再加错误顺序/错授权失败。原 T321 suite construct + pair oracle + replay 不得破坏。
- **成果**：`T321_MULTISTAGE_PROOF.json` 至少一对实跑双臂 + 一份故意失败事件链。

## M2 · 可组合 WorkflowPlan → IR → Runtime（核心攻坚）

- **新增尽量仅** `src/ioabench/v5/ai_generation/workflow_modules.py` 和 `workflow_compiler.py`（可依实际命名），复用 R2 的 scenario_tree、binding 和 IR。
- `dynamic/business_tools.py::_flow` 不再依赖 `BUSINESS_FLOW[root]` 静态完整序列：按编译过的 binding 执行 stage modules ；compiler 遵照 module tool/schema/权限/证据/分支前置。
- `tree_factory.py::treatment_messages/propose_payload/run_task` 强制让模型提出 WorkflowPlan（不是由程序事后伪造 plan）。R3 `baseline` 路线按旧计划兼容包装但不得冒充模型自主生成。`candidate_ir` 与 MechanismIR 增加 workflow endpoint/provenance 绑定；任何 plan 校验失败不得到达 suite compiler。保持原 CONTROL/RISK 风险槽。
- T331/T362 使用同一 generic workflow compiler，suite-specific 仅提供受测 actor/event hooks，不能再为两套件分别硬写相同三步业务列表。
- **测试**：不同 DAG 的真实事件图差异、一个 join 缺支拒绝、一个合法条件分支执行、同图换名 hash 不变、跨行业工具错配拒绝、IR/compilation 无旁路。
- **成果**：每套件至少两个**原 R2 不具备**的合法执行 workflow 家族 `WORKFLOW_PLAN.json`、`COMPILED_WORKFLOW.json`、真实 trace。

## M3 · WitnessVerifier 与旧审核最小改造
