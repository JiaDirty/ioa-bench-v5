# ZCode Goal｜IoA-Bench v5 树状机制生成工厂试点

> **重要：这是供 ZCode Agent 阅读和执行的任务契约文件，不是 ZCode 自动识别的特殊文件。** ZCode 的 `/goal` 需要用户在对话框里显式设定；具体指令见 `08_ZCode启动指令.md`。

## 唯一目标（一句话）

**在既有 IoA-Bench v5 内，以 T331、T321、T362 为试点，将受限线性/枚举式生成升级为「依赖约束的树状场景规划 + 版本化 typed MechanismIR + 可执行编译与设计-执行见证 + 确定性事实核验与同源语义审阅 + 有界失败反馈」的可复用研发数据工厂，使用 AIHubMix `deepseek-v4.1-flash-1017` 完成冻结任务的新旧方案真实对照，并保全原始数据、18项规则、Git 与请求账本。**

## 完成定义——以下每一项均需真实证据，缺一不得报告 GOAL_COMPLETED

G0. **基线和权限**：读取 `AGENTS.md`、最新 `state/PROJECT_STATE.yaml`、`state/WORK_QUEUE.yaml`、2026-10-23进度和本包；检查并记录本机 Git HEAD、运行源码哈希、未跟踪文件和历史资产范围。不得把打包基准 HEAD 强认作本机当前 HEAD；若本机更前进须先安全合并计划。创建隔离新分支或精准提交，不改用户历史。

G1. **Provider 恢复并证明**：从 `AIHUBMIX_API_KEY` 安全读取凭据；确认 `deepseek-v4.1-flash-1017` 的 authenticated ID/schema、`openai.chat_completions`、允许的 effort、JSON 收据，新的最小 Completion 收到真实 HTTP 200、匹配 served 模型和 usage。401/403/REQUEST_UNRESOLVED 停止全部新付费请求。此关不能通过时，**Goal 保持 BLOCKED_PROVIDER，而非已完成**，继续零付费工作并交准确排障材料。

G2. **树状规划可执行**：实现可验证的有向依赖分支（行业→业务义务→角色/资产/权限→工具/证据→拓扑/时序→风险干预），至少包含两个**语义联动的大段业务分支**；选择不同根分支时，下游工具、数据、义务和事件一致联动，不许只是换词。结构选择可用 seeded 随机或覆盖引导，但必须可复现、可静态发现非法组合、能解释选择概率与覆盖缺口。

G3. **机制 IR 与真实执行见证**：新增有版本的 typed `MechanismIR`、`CompilerCapability`、`DesignAssertion→CompilerBinding→ExecutionWitness`。先支持 T331，再推广 T321、T362；不破坏旧 `Blueprint` 和已通过的旧 schema。至少各试点**2个在旧基线未覆盖、确由运行时消费并产生可验证差异**的新结构单元；如实际语法/执行能力不足，保持 `CAPABILITY_GAP`，不得以表面故事充数。每种结构必须包含反事实/负控、双臂参考、逐事件见证、strict Replay。

G4. **审核可信和修复可控**：引入程序求值的真值谓词、证据摘要和断言-证据一致性验证；修复已知“合法引用但结论与事实矛盾仍通过契约校验”的缺陷。固定6个历史负例以及独立设计的新负例，在硬门和审核契约上全部不被误接受；同时引入预注册**有效正例**来测误拒，不得通过一律拒绝完成。禁止覆写原审核结果/硬门；失败反馈只允许新 candidate ID、新请求账本、限定次数的独立重规划/格式修复，历史 UNKNOWN 不重发。

G5. **真实研发闭环**：通过 AIHubMix 实际调用新模型，在**冻结、对等任务列表**上对比原 G2 和新树状 IR 路线；两者都要经过相同的 hard gates、历史去重、同源审核和 Replay。各试点至少尝试 3 个独立新任务（原则上新旧各一组配对机会），每试点至少1对**全新** `DEV_ACCEPTED` 且有不同被消费执行结构；不混入旧32对、已存在19对，旧样本不可重命名计数。真实线上先从 T331 一条新候选开始；完成安全检查后再扩展，不能因“任务长”直接量产。

G6. **公平量化及可复用**：提供结构/业务分支/执行边同构类、设计-执行 fidelity、前阶段拒收率、生成→工程→审阅→研发入池漏斗、每条新增 DEV_ACCEPTED **全链路成本**（含失败/审核）、延迟、tokens、异构预算，以及旧/新方案不删失败的对照。固定历史无法投影（T322的5.1.0）继续 `VERSION_SCOPED/INDETERMINATE`，不能谎称18项全历史验收。18项注册能力和扩展 TODO 需可审查，不要求本轮把14个2单元套件全部开发完成。

G7. **回归与交接**：已有受影响测试+本轮新增反事实/负例均 PASS；跑全量 v5+m1 回归并记录真实分母（不可借用旧1844项冒充本轮）；冻结试验绑定版本、哈希、实际 API 收据、可脱机重放/零请求恢复；提交代码至本地 Git（**不 push**），输出报告、机器可读数据池索引、对照和验收表、凭据扫描、交接 ZIP。历史记录不得更改，writer lock 最终释放。没有真实证据写 `FAIL/NOT_RUN/BLOCKED`。

## 不可更改的边界

- 18个风险构念及已有 Oracle、scorer、正式 SUT 配置不修改、不降门槛；T361–T363 维持 `SIMULATION_ONLY`。
- CONTROL/RISK 必须仅改变声明的可执行风险干预；不能让不同业务根分支分别落到CONTROL与RISK（那是多因素混淆）。**先选整棵业务/机制树，再从同一根实例克隆两臂**。
- 不使用纯粹行业名、句子、seed、role ID、工具名重命名充当新结构；必须检验 canonical graph 的同构、具体运行时消费及行为证据。
- 不让模型自由提交可执行 Python 并在主宿主机执行；新构件必须走有类型 registry / 受限编译器与沙箱工具。
- 同源审核获用户授权作为研发筛选，但不能称为独立科学结论；Gold/PI不作为此次研发入池前置，正式科研资格状态保持明确。
- 不打乱源码、破坏已封存样本或请求终态；404/429/5xx/401/UNKNOWN分类严格，**禁止自动重发未知终态 POST**。

## ZCode 迭代规则

每轮按 `03_任务队列与源码落点.md` 的 M0→M7 顺序作代码/测试/证据，更新机器可读 `GOAL_PROGRESS.json`（完成、阻塞、证据、下一步）。Goal 状态不能仅凭计划、README 或 mock PASS 判定；模型调用成功不等于工程入池；程序预检结构不等于模型真实生成结构。遇到可处理的代码问题继续做，外部鉴权/账号阻塞零付费停机并保留全部结果。若真正触及预算硬停，停止新请求，留下准确未完成状态供用户决定，绝不改成 PASS。
