# 数据生成流程审查与改进 — 2026-10-14

结论：现有流程能够生成、编译、运行和独审实验候选，但还没有充分实现“18项稳定、批量、高质量且多样化的数据生产”。当前最重要的限制是可生成的真实结构偏少、独审尚未完成在线正负控制，不是再换一个生成模型。本轮审查补齐了六处明确工程/审核输入缺口，未调用AIHubMix，未改原数据、GT、评分或既有审核结果。

## 已确认并修复

| 发现 | 原来可能发生什么 | 当前处理与验证 |
|---|---|---|
| 独审缺少测评定义 | 提示要求评估construct_fit，却只给Txxx编号和案例；审核者缺少权威定义及相邻构念排除边界 | 从contracts/v5/construct_maps.json原样提供5个公开定义字段，附原始版本、draft状态和文件SHA-256。18项定义一致性及跨测评混配拒绝共19个回归。仅独审可见，不发送给被测模型，无Oracle/判分答案 |
| 历史参考缺失被静默跳过 | 文件删除后参考池缩小，可能误判结构新颖性 | 必需历史文件缺失立即报错，在发起Provider前阻止运行；两个反例回归 |
| 参考池缓存未独立绑定 | 中断后BASELINES或历史hash列表改动，可能影响后续候选比较 | 新run增加BASELINE_MANIFEST，绑定参考池及来源清单；续跑重新核验历史文件hash，缺失/改动在Provider创建前拒绝；三个反例回归 |
| 接受结果的证据清单可漏项 | 删除某条hash绑定，甚至连同审核文件删除，旧检查仍可能把结果当成完整接受 | 校验绑定清单与实际证据文件集合一致；机器接受必须保留完整生成/编译/硬门/参考执行/独审证据；两个反例回归 |
| 异常结束仍可能被接受 | 响应返回合法JSON，但finish_reason缺失、error或tool_calls，旧流程仍可能接受 | Chat辅助调用必须正常stop；原拒绝、过滤、截断分支保留，异常原响应留档、不自动重发；生成和审核两个角色共六个反例回归 |
| 质量控制脚本未接住响应拒收 | 截断、拒绝、身份不符等从共用调用函数抛出后，控制脚本直接退出，未生成终态诊断 | CONTROL_RESULT记录REVIEW_RESPONSE_REJECTED、原阶段、用量和证据；passed=false，不能把“响应不合规”当成“成功识别矛盾”；四个反例回归与API0续跑验证 |

这些反例先在修复前复现：13个产线/缓存反例、4个质量控制响应反例和19个定义输入反例。中间一次测试夹具因引用了临时工作区之外的数据路径而失败，随后改为在夹具工作区内放置所需参考数据；没有放宽生产校验。所有初始和中间测试XML均保留。

版本：factory2.3.5、generation-quality1.4.0、quality-control1.4.1。公开定义属于既有构念的审核上下文，不是新的构念、Ground Truth或评分标准。其GATE_A_DRAFT_PENDING_EXTERNAL_REVIEW状态原样保留。

## 仍应优先改进

1. **增加可执行结构，而不是只扩充文字。** 全部18项有文字补充入口，但大多只能在一个既有字段后追加不超过240字符的中性上下文，不能生成新工具、任务或证据路径。三项typed编译器中，注册失真主要改变业务参数而非结构；跨系统级联扩散支持扇出2/3，声誉垄断支持分配者2/3及广播/本地回执两种证据方式。T321另有独立编译器，但没有接入这个统一入口的typed选择。应逐项把已有动态能力暴露为受约束的可执行参数，再让模型生成。详见CAPABILITY_INVENTORY.json；现有能力不等于任意蓝图编译器。
2. **生成前先选覆盖目标。** 当前统一CLI明确是最多6个候选的小批技术入口，typed试验固定M和少数trial_target；它不是完整批量计划器。应复用现有CoveragePlanner及覆盖矩阵，按机制/任务/证据/交互组合选择目标，避免重复付款后才发现都在同一结构。设计E/M/H标签与实测难度是两件事，仍需行为数据校准。
3. **先验证审核者能拒绝坏样本。** 一例PASS不证明审核可靠。已有verify_data_factory_quality.py提供盲注入矛盾控制，但当前在线正负控制尚未充分验证，且只支持两项。应为固定审核配置预先确定正例和多种缺陷负例，保留所有判断，验证漏检及误拒，再扩量。新版定义输入尚未在线测试，旧PASS不追认为通过新版独审。
4. **统一全历史结构索引。** 当前CLI比较经典5.1.5/T3325.1.6、动态种子和trial目录中的已接受候选，未覆盖全部其他历史生成命名空间。先前被拒样本中“程序有效但审核引用失败”的结构也可能再次出现；它们可以作为“已出现结构”证据，却不能冒充合格数据。应复用注册表存储，保留质量资格与结构身份的区别；不要把旧family_registry的hash字符距离用于语义近邻，当前quality.py的实际运行特征比较应继续保留。
5. **缩短独审输入并保留可核查证据。** 旧6个审核用户提示约12.9–14.9万字符，案例视图约3.3–3.4万字符；完整路径索引及参考元数据占大量空间。可压缩重复参考说明、按维度提供相关字段索引，但必须验证没有删掉关键世界证据、因果对照或引用能力，再做固定控制集的在线比较。本轮没有为了压缩而删除证据。

对“同结构的新实例是否合格”与“新结构家族是否增加”应持续分别记录。不能把描述不同当成新家族，也不能通过降低独审分数阈值来填满配额。本轮保持既有门槛。

## 接下来做什么
