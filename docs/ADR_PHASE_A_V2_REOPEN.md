# Phase A V2: reopen construct acceptance

Date: 2026-09-27. Status: accepted implementation direction; scientific acceptance remains open.

The previous offline gate is insufficient. A fixed-seed input audit finds identical mechanism and difficulty payloads in T312–T363. T311 has five mechanism payloads and three difficulty payloads, which alone does not establish causal validity. The formal CLI still blocks real models and routes mock runs through the legacy executor.

All historical datasets, runs and artifacts remain immutable. `artifacts/gates/V2_A00_BASELINE/inventory.json` records 16,414 historical file hashes plus source and contracts. Tests that write repository artifacts run in an isolated workspace; they must not rewrite historical acceptance evidence. The initial Windows baseline is 396 passed, 2 integration tests excluded. Windows asyncio needs loopback sockets; the offline harness allows loopback and denies external connections.

The work queue preserves historical completion records and adds V2 acceptance and campaign tasks. CIG-R6-ENTRY depends on V2-A07. T311 dataset 2.0.0 is provisional pending the new construct audit; the earlier online pilot is exploratory and reported INVALID_MODEL_OUTPUT. Neither counts as final scientific completion.

T312 generation now constructs explicit registry claims, independently inspectable task receipts, and programmatic suitability. Its five interventions are keyword repetition, visibility, duplicate registrations, false suitability, and reputation metadata. Control/risk pairs hold task and independent evidence fixed. The adapter consumes these records instead of substituting a constant candidate world. The new selection runtime separates physical task results from Oracle scoring, checks role tool permissions, removes the condition label from the initial model input, and uses runtime/replay version 2.0.0/v2. Existing frozen files are not regenerated.

The initial T312 checks cover all five mechanisms at three difficulty settings, selected-agent and Sandbox consequences, alternative safe completion, Oracle-only perturbation, and unauthorized executor tools. Candidate-count and receipt-count differences reach actual tool responses. This is partial A02 evidence, not a claim that all difficulty, contract, replay or formal-runner obligations are complete. Remaining suites require their own causal worlds and verification.

T313/T323 now use a shared versioned raw-grant world and multi-hop executor. Their previous implementation reconstructed visible faults from Oracle flags and called only one requester-driven decision path. New generated cases carry independent source archives and explicit grants; the adapter copies these fields without consulting hidden verdicts. Issuer sessions decide each grant and dispatch, recipient sessions receive only their chain prefix and task, and the terminal executor makes its own tool call. Chain depth and the location of the defective middle edge vary with difficulty. Scope/resource/audience/expiry/principal and provenance fields have distinct interventions. Issuance, revocation, repair and task effects are persisted and scored separately. The old fixture runtime remains for historical tests and must not be selected by the future formal dispatcher for v2 worlds.

T321/T322 now have versioned protocol executors. Negotiation requires both tested participants' consent to one configuration, explicit termination before fallback, and a persisted business operation for utility. Interoperability maps raw source/target receipt semantics and idempotency keys into actual ledger changes; compensation reverses a specific pending effect rather than merely setting a status flag. Oracle labels do not construct their visible protocol worlds or physical results. This replaces the earlier Oracle-driven mapping and generic duplicate-write fixture for new v2 generated cases; formal dispatch migration remains pending.

Typed protocol booleans and null fields are not textual Oracle verdict disclosures. The leakage detector still rejects explicit hidden keys and copied textual hidden values, but does not infer leakage solely from a public typed boolean/null matching an unrelated hidden verdict. Differential Oracle-only perturbation tests independently verify that hidden labels cannot change model inputs or physical state. This corrects a false positive without changing deduplication or quality thresholds.
