# 面向效率的最小工程纪律

用户已明确：**不需要成本限制，不希望以防御性编程和重复审批拖慢工作**。ZCode 应直接修改源码、编写最少必要测试、运行并继续推进，不必每小步都询问。

## 直接做，不要做

| 直接做 | 不要做 |
|---|---|
| 基于 `49d096e` 后的最新工作区增量修复 | 从零搭建第二个数据工厂或一套全新网络SDK |
| 一条主链 `Tree→IR→Compiler→Runtime→Gates` | 在新旧两条在线路径间隐式 fallback，导致新版验证被绕过 |
| 用2–3个关键反例证明完整验证起效 | 给每个简单字段加多层适配、缓存、虚设保护层 |
| 使用标准 ModelPort/SSE、原有 Replay/Oracle | 为规避一个具体错误修改评分阈值、替换历史数据 |
| 精简审核包，收紧真实可验证的 evidence claim | 把几MB原始 log直接塞到每次审核提示词中 |
| 假设资金充足、允许充分模型调用 | 让5/20美元停机影响实验；为了省钱压到16K输出 |
| 先做真实可执行结构，再生成长文本 | 先生成几十KB故事，最后才查编译器支持与否 |
| 新候选 ID 修复已知确定失败 | 重新发送旧 UNKNOWN 的 POST 或修改请求账本 |
| 写易读函数、原有包内的小补丁 | 创建数十个新 registry/proxy/validator 来模仿“安全工程” |
| 一套当前 HEAD 的真实回归 + 关键专项测试 | 对相同冻结数据反复跑模型直至偶然 ACCEPT |

## 保留的6条底线

1. 一对 CONTROL/RISK 只在声明的风险干预上变化，业务背景配对相同。
2. 原历史去重、Oracle、防泄漏、因果门、strict Replay **任何一个不能被模型覆盖**。
3. 真实结构必须能在运行时看到，不能只写在 Prompt/IR 元数据上。
4. 已发送但终态未知的 POST 不重发；旧 STOP/账本/历史只读。可用**全新任务 ID、新运行目录**推进独立新样本。
5. 自动审核不得把程序事实矛盾样本判成有效接受，同模型研发审核不能号称独立科学验证。
6. Key 不入 Git/交接包；历史文件不可清空覆盖；T361–T363 `SIMULATION_ONLY`。

这些不是“过度防御”，而是让最终数据能用于研发评估的**最小科学与运行一致性条件**。

## 自治决策授权

- 模型普通协议参数错误、短输出截断、格式错误、编译器 capability gap、单元测试失败：**ZCode 自己诊断、修复、重跑该步并推进**。
- 改业务 binding/IR、调整输出到131/262/384K、切 high/max、新 run 下安排更多独立任务、并发1→2→3：**不用请求逐项批准**。控制的是事实正确性，不是花费。
- 外部身份权限失败：保留证据，做所有离线可做任务；既不能伪造恢复，也不要无限请求同个401 ID。
- 把文件推到公开 GitHub、覆盖历史证据、改正式科研构念/评分器、泄露密钥：**不在本轮自主权限内**。

## 避免重复元数据

只维护 `R2_RUN_CONTRACT.json`、`R2_GOAL_STATUS.json`、统一 `REQUEST_LEDGER.jsonl` 和必要逐候选证据。历史形式多套清单可以读取，不需要再生成四套互相印证的同一 SHA 清单。最终让另一台机器用一条命令快速验收 R2 核心链。
