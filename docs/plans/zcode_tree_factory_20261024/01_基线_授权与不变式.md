## B. 会议需求对应

| 会议诉求 | 本轮实现位置 | 可观测验收 |
|---|---|---|
| 线性关键词替换 → 树状结构 | `ScenarioBranchTree` + constraint resolver | 不同根分支产生相互一致的业务/工具/数据流，不跨界混搭 |
| 大段可替换模块 | `DomainWorkflowPackage` 带 version、业务义务、工具schema、资源生命周期 | 至少医疗与金融两套真实分支，改变的不只是文案 |
| 上下游内容动态联动 | typed `DataBinding`、依赖图、事件 witness | 业务资产ID/对象类型/权限/回执字段全链路一致 |
| 低成本程序化生成 | seed + branch coverage planner + static dry-run | 同样输入得到相同候选；早期失败不浪费四阶段调用 |
| 提升多样与随机性 | 结构 cell 配额、同构归一、pair witness | 合格新增结构与旧结构不等价；不靠行业名等表层因素 |
| 测评维度 review | 独立 proposal 文档 | 18项本轮不删改，研究负责人审批后另设迁移计划 |
| GitHub 代码/私有数据协作 | 受审计的 Git 手册 | 本地 commit，公开仓库绝不夹带私有数据/Key；push由用户明确决定 |
