# 05 · 质量优先：模型规划、生成与审核的可靠调用

## 分清两种模型

- **ZCode GLM-5.3**：编写、测试、提交代码与本地报告；具体思考等级由 ZCode 产品能力配置，不把 DeepSeek 的 `reasoning_effort` 字段错发给 ZCode。
- **AIHubMix `deepseek-v4.1-flash-1017`**：提出 `WorkflowPlan`、编译器已允许的 `suite_payload`、业务材料，以及同模型不同档位的**研发**语义审核；模型不能控制 oracle/scorer、干预真值或受保护历史。凭据只在环境中，不进入提示词或导出。

## 主要瓶颈不是 API 价格，而是每次成功请求是否产出可用工作流

费用约束取消，`BUDGET_GATE_ENABLED=false` 沿用 R2，不再做美元预算阈值/余额作为用户人为停机；但 `401/403`、真实余额不足、请求终态未知、接口返回无可验证终态等情况属于**事实故障**，不能为了“不断跑”而隐瞒。原 R1/R2 STOP、UNKNOWN 请求、账本只读。新 R3 run 和 request_id 不得复用原 UNKNOWN。

## 推荐参数（起点，不是恒定绝对值）

| 角色 | thinking | max_tokens | 备注 |
|---|---|---:|---|
| WorkflowPlan /复杂 DAG 规划 | high | 131072 | 模型上下文可按需要传递行业/工具 schema/实例，不锁死输入120K |
| 复杂依赖、跨领域一致性回评 | max | 262144 | 只有网关确认接纳 max 档后启用，否则使用实测兼容档并标注 |
| SuitePayload/业务材料 | high | 131072 | 一次只生成最必要材料，避免巨大任务把审阅拖成长期连接 |
| DEV 审核语义版 | high/max | 131072 或 262144 | 程序事实先压缩提要+可核证指针，模型不重复计算全部事实 |
| 极复杂单次请求 | 网关支持档 | 最大393216 | 若 131K/262K 有真实截断证据且任务确有需要才升至上限；不必强制输出满额 |

**上下文**：从真实模型/网关可用能力出发，允许使用原生约1M上下文，不给程序再设人为短限制；实践中送入**相关证据 + 可追踪摘要 + 对应引用**更高效，避免把数十万重复日志盲目灌入。`context_window≈1000000` 是能力声明，并非已在 R2 满载验证。

**输出**：`max_tokens` 是推理与正文共享的上限（以当前网关实际行为为准），不是每次必须生成的长度。网关“接受393216参数”≠“已经验证连续输出384K正文”。`finish_reason=length` 时必须单独归类，保存 reasoning/正文/usage、能否 JSON parse 的真实结果。使用**按阶段高上限+可审查中间产物**，不再依赖硬16K来节省费用。

## 在线流程（无新的并行SDK）

现有 `aihubmix_study.py` / 适配器 SSE / `tree_factory.py` 直接扩展：

1. 程序按目标格与环境模块目录决定 candidate 的可用工具/角色/数据范围。
2. 给 DeepSeek **模块元数据**与结构化 `WorkflowPlan` Schema，要求不同合理拓扑/因果可解释、不能越权；保留静态创新目标但不能把 exact DAG 预先给模型照抄。
3. 模型提议后先本地类型/权限/DAG/可编译性检查。若非法，用**最小错误列表**指导新 ID 一次或有证据的少量修复；不要为修复编一份巨大的审计报告。
4. 编译/Reference Replay 与 hard gate 先过，再决定是否需要昂贵的语义审核；失败候选不会被后续 model ACCEPT 洗白。
5. AI 审核只面对事实摘要、必要原始材料及哈希引用。保持同源研发的限制，版本化校准，保存两档原始结果与分歧，不盲目合并“两个同源模型”作独立性。

## SSE 真实性与重试界限

- **只有完整 SSE 终态、明确 usage/finish_reason/内容与 schema** 才算真实已完成请求；网络 reset、EOF、curl 35/56 或响应半截要记 `UNKNOWN` 或准确 terminal category。
- `finish_reason=length` + 明确完成是**已知截断**，可在新 ID、足够 output ceiling、适当缩任务的条件下有目的重试；不能把它误记成 transport UNKNOWN。
- **同一 POST 终态未知不得无证据重复发送。** 新生成任务可以用新的候选/请求 ID 推进，不因旧 STOP 冻结整个研究工作区。
- 不把网络错误猜测成 AIHubMix 服务端根因，保存 request timestamp/model identity/HTTP/SSE evidence。
- 统计高/最大档的成功率、P50/P95 完成时延、reasoning/completion token、非空 JSON率、工程有效率、审核通过率。花费仅用于**观测与科研报告**，不当停机门槛。

## 审核精简但质量不放松

将程序能确认的事实（合法工具/顺序/角色/来源/配对/score/oracle/replay/dedup）汇总成**短且有指针的 facts packet**，语义审阅只回答：`BUSINESS_COHERENCE`、`CAUSAL_PLAUSIBILITY`、`MECHANISM_RELEVANCE`、`SURFACE_REALISM`、`ROLE_MOTIVATION` 和引用证据。不将 10MB 重复日志全部拼给模型以致思考无暇输出 JSON。用真实离线校准证明至少负例、正例和实际 T321 争议样本不误判；审核前后的真正失败原因分开统计。
