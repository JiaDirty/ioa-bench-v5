# 07｜交接与验收文件规范（由ZCode在用户工作区实际生成）

**目录建议**：`artifacts/v5/tree_factory/<fresh-run-id>/`；所有文件可用新版本附加，不修改已封存原件。

## 提交前必备

1. `BASELINE.json`：原HEAD/工作树状态，真实 runtime SHA、保护范围、当前GoaI源包SHA；不得假造本地与快照相同。
2. `GOAL_PROGRESS.json`：每一个 M0–M7 / G0–G7 的 `PASS|FAIL|BLOCKED|NOT_RUN|PARTIAL`，证据指针、阻塞、下一轮动作、费用与外部约束。
3. `LIVE_MODEL_CONTRACT.json`：AIHubMix当前真实凭据有效性、认证后catalog、servedID、endpoint、model schema SHA、合法effort、max tokens、请求参数和实际usage。**只记录密钥存在标志，不能储存Key。**
4. `TREE_SPEC.json`、`BRANCH_DECISIONS.jsonl`、`TREE_CONSTRAINT_REGRESSION.xml`：至少医疗/金融真实业务流的条件树、程序消费证明。
5. `MECHANISM_IR_SCHEMA.json`、`COMPILER_CAPABILITIES.json`、`ASSERTION_WITNESSES.jsonl`：IR版本、3试点capability、每条非表面声明绑定和正/反事实witness；附旧结构比对。
6. `REVIEW_FACT_PREDICATES.json`、`AUDIT_CALIBRATION.json`：硬事实、合法引用、论证一致性、原6及新≥12负例、正例≥6逐条错误和有效引用证据。
7. `TASK_SET_FROZEN.json`、`AB_PREREGISTRATION.json`、`AB_RESULTS.csv`：两组方案等机会、冻结任务清单、任务终态及原始SHA。
8. `NEW_POOL_INDEX.jsonl`、`PAIR_QUALITY.csv`、`STRUCTURE_CELLS.csv`、`FAILURE_FUNNEL.csv`、`COST_AND_YIELD.json`：新增/既有分账、结构与行为签名、工程/审阅/入池分母、费用估算和未知项。
9. `REPLAY_RESUME.json`、`HISTORY_PROTECTION.json`、`FULL_REGRESSION.xml`、`SOURCE_MANIFEST.json`、`EVIDENCE_INDEX.json`：严格Replay、终态恢复=0新请求、历史SHA、真实回归分母、代码哈希和证据索引。
10. `SUITE18_CAPABILITY_READINESS.csv`、`ROUND_REPORT.md`、`NEXT_ACTIONS.md`、`HANDOFF.zip`：15套件扩展路线、状态报告、最多3个真正外部所需动作、原始产物打包。ZIP要验证CRC、逐文件SHA、独立解压导入、秘密扫描；大型旧数据可外置但必须标清哪些没有打包和验证范围。

## ROUND_REPORT.md 固定问答

- **有没有真实提供者Completion?** 请求及响应数、HTTP成功数、servedID匹配数、终态未知数、401/403数。不能拿目录可见代替成功。
- **有多少新结构是真的在运行时消费？** 按T331/T321/T362的新增结构单元及witness的源文件SHA，不混入“只改行业文本”的数量。
- **设计是否兑现？** 逐条声明的PASS/FAIL/UNOBSERVED，典型负例与对照轨迹。
- **为什么被拒绝？** JSON/schema、编译能力、干预、历史、Replay、事实矛盾、AI引用/语义按漏斗展示，保留失败分母。
- **研发入池多少真新增？** 新ID + 新真实请求+新审核全部完成，排除旧32及旧19，列硬门/审核状态。
- **新旧效果如何？** 同题机会/付费请求/结构单元/入池/成本/延迟/失败率；对照能力边界与统计不确定性。
- **18项剩余什么？** 列14项有限语法瓶颈、T322历史版本隔离、T361–T363模拟-only、PI review仅提案。
- **何时可以结束ZCode Goal?** G0–G7均有能独立复核的 PASS；单独因外部问题 BLOCKED 时必须明确说明无法完成而非写“成功”。

## 源码与仓库管理要求

- 本地分支保留完整Git历史，`git diff --check`、本地commit（不push）；不加入 `.env`、Key、Token认证头、终端日志的原始Secrets、原始私有凭据或用户无关未跟踪目录。
- 不直接清理含引用链的旧 artifacts。若版本迁移则采取新目录+source binding；删缓存只允许白名单且确保可重生。
- 由 ZCode 先做源码落点对照，若本机 HEAD 已改变，需要更新本轮代码路径/测试准确性，但不篡改用户的权威现有版本。
