# 动态 IoA 世界、自由 Agent 执行与全局科学监测：可落地架构契约

## 1. 问题与边界

现有 v5 `Case(world, oracle, mechanism_slots, fingerprints, ...)`、`Scenario.agents/tools/initial_state/opening/budget`、`EnvContext.state/events/deliver`、`ActionRecord`、`Trace`、`check_pair` 和18 Suite 已经提供基础。被测 Agent 目前也有自主选择现有工具及顺序的能力。**缺的不是再造一个聊天代理，而是让不同样本产生不同的有效世界状态、工具行为后果、证据可见路径和多 Agent 协作拓扑，同时确保全局计量客观。**

以下是**目标接口草案**而非已核实存在的新源码：ZCode 应对照最新真实代码设计最小兼容实现，不能照文字机械引入全新框架。

## 2. 六层职责，物理部署可合并

1. **科学构念层**：18 construct maps，每项明确测什么、不测什么；CONTROL/RISK 单因果机制、合规事实来源、潜在混淆、允许的行为及失效定义。锁定已批准版本。
2. **场景规范层**：版本化场景 Blueprint 与 Suite capability map。实体、关系、角色权限、任务目标、操作依赖、证据来源、时间、信任边界、风险干预、工具可用性，不含可执行任意代码、模型自定 GT。
3. **世界编译/执行层**：经审查的能力组件（如消息、身份/授权验证、目录查询、协商、资源发送、调度、状态转换、声誉、论坛和历史任务队列），组合成有状态且隔离的 IoA 环境；有前置条件、确定性或显式受控随机转移、效果与错误；Agent 可自主选择动作。
4. **全局事件/可观测层**：统一记录 Agent 输入/输出、路由、消息、工具请求/返回、调用主体、授权链、状态变迁、证据何时可见、关键后果、预算/异常及随机/版本来源。所有边界内外部作用都经环境仲裁。机密 oracle 在不可见审计通道，绝不泄漏模型提示。
5. **评估层**：通用的完整性、可重放、因果配对、暴露/机会与分母处理；Suite 专属事件/状态谓词测量安全性、效用与恢复；允许多种正确行动路径、谨慎弃权及不判分状态。
6. **证据/统计层**：每一轮 content hash、运行配置、模型实际身份、事件日志、监测结果、评分、拒收、原始响应与统计分母；统计使用配对、family 聚类和不确定性区间，不能将每次工具调用算独立样本。

## 3. 类型化场景表达而非固定流程模板

建议支持如下声明性结构（字段名仅设计示例，最终以 Case 当前数据契约和兼容性审查为准）：

- `world.entities / relations / resources / policies / authorities / clocks`：外部事实与权利结构。
- `world.agent_network`：角色、组织、消息路由、信息不对称、信任/委托边界、可见工具；支持单 Agent、多 Agent、代理/模拟对手、长程队列。
- `world.capability_instances`：由经过测试的工具模板装配，实例化对象 ID、前置条件、状态转移、返回证据；不得让生成模型插入无审计的 Python、Shell、URL 或任意执行器代码。
- `world.evidence_graph`：事实主张、来源、权威程度、访问权限、出现时机、冲突/撤销/过期、证据间关系。区分真相、Agent 可见信息和 evaluator 私有信息。
- `world.task_contract`：业务目标、成功谓词与合法替代路径。目标与风险操纵必须能独立于固定 witness 行动序列定义。
- `intervention_spec`：对照与风险仅允许在指定证据载体、授权索引、目录呈现、协商 offer 等**预注册机制槽位**变化；具有限定差分与非预期干预检查。
- `oracle_contract`：由预注册事实与合规规则计算、版本化可审计，禁止由 AI 文本结论直接决定。
- `observability_contract`：外部状态事件、暴露事件、决策机会、检测不可见/不可判定的边界。

`task_graph` 是业务依赖/目标前置条件，**不是强迫模型按图执行的脚本**；编译时必须标明哪些节点/约束/证据已具体落地。无法实现的有效关键提议必须标记 `CAPABILITY_GAP`；禁止静默丢弃后仍认为场景新颖。

## 4. 自主执行与事件账本

动作语义：Agent 在可用工具与预算内选择动作；执行器验证调用主体、权限、参数、前置条件与当前世界状态；原子应用效果、记录前/后状态摘要及明确错误。工具可读可写，但仅作用于可复位沙盒，避免真实副作用。

建议最小标准事件：`run_id / case_hash / suite_id / episode_id / event_id / parent_event_id / agent_id / timestamp_or_logical_step / channel / action / inputs_digest / visibility / authority_reference / state_before_hash / state_after_hash / effects / error / tool_result / provider_metadata`。实际字段遵循现有隐私策略，避免把机密/隐私的明文无必要复制到日志。需要保留因果边和稳定事件序号，而不止纯文本 trace。

必须覆盖：

- 跨组织消息转发和授权链的事件来源/责任主体；
- 条件失败、拒绝、重试、恢复、撤销、过期、并发或重复调用；
- 动态环境反馈，包括危险操作的持续性后果；
- 曝露刺激是否真的送达被测模型、是否具备有意义的选择机会；
- Agent 提前停止、无操作、错误工具、budget/timeout/截断与基础设施失败。

**“全局监测”只能覆盖由受控环境捕获的可观察行为和结果，不声称知道 Agent 私有思想、外部未接入渠道或不可观测现实世界事件。** 未观察或无机会必须标为 `NOT_OBSERVED / NO_OPPORTUNITY / INELIGIBLE` 等非假阳性状态；具体沿用 v5 当前 outcome 合约。

## 5. 不依赖唯一“正确路径”的评价

- **通用层**：回放与日志完整性、事件关联、实际工具结果、暴露、机会、可用样本分母、基础设施健康。
- **Suite 层**：规范触发条件+执行中行为谓词+外部世界后果，判 `safety / utility / recovery` 三轴并分离未知/弃权。
- **Oracle 层**：依据权威政策/事实决定是否授权，不从生成模型的叙述、被测模型的答案或 witness 的表面动作推导。
- **多条合法路径**：拒绝危险 offer 后安全重谈、有效例外分开传输、选择其他供应商等只要合法且实现任务就算成功；不要求执行固定调用顺序。
- **参考策略**：witness、naive、recovery 用于验证环境可辨识及判分灵敏度；必须再有反例、替代安全路径、无操作、错误环境状态的测试，避免为适配 witness 扭曲生成世界。
- **全局时序监控**：对于“在未经许可前不发送”“在看到权威证据后再决定”等性质，可用确定性有限状态监视器/事件谓词；具体时间窗口与可见性必须 Suite 预注册。不要引入不可审计的通用 LLM judge 取代关键硬判定。

## 6. 验收及负面测试（至少）

1. 同一世界支持多条不同合法动作序列，并取得一致安全/效用判定；模型无需遵循 witness。
2. 一次越权/错误传输不因后续安全操作被从历史里抹除；恢复按预注册规则独立报告。
3. RISK 操纵可以稳定触发可验证的差异；CONTROL 未意外改变任务难度、可见证据或权限链。
4. 日志中每个发生副作用的工具调用都有完整事件；故障、预算耗尽、并发及恢复可确定性解释。
5. 更换实体名、行业说明但不改变实际执行结构，结构性去重正确识别为同 family。
6. 新任务图和证据链若无法落地，编译器显式拒收 `CAPABILITY_GAP`，不伪造独立家族。
7. 通过动态消息的各类提示注入/越权文本仍不能污染 evaluator/Oracle；防泄漏门槛有效。
8. 从固定种子与完整版本清单能够复放相同的环境工具轨迹，非确定性 Provider 输出及模型采样则以不可重现原始响应的不可控边界如实记录。

先在 T321 做一个真正可执行的增强垂直切片；再选不同构念（例如 T312/T323）检验共用层。不要把 T333 已存在的自由文本弃权问题绕过；若使用 T333，需单独 scorer audit。
