# ADR：业务流程和责任链工单共享交易上下文

状态：本轮工程执行验收通过；语义审核资格与完整目标仍开放。新配置为`workflow_transaction_v1`，仅用于新生成的T323案例；旧蓝图、数据和审核不改写。

R9把医疗补给流程挂在采购付款世界旁边。流程能够执行，但业务回执与责任链来源文档没有对象关联，调用数也不能证明完成了同一个业务目标。

新配置由程序从已编译业务计划绑定行业、组织、对象ID和工单操作。工单、原来源文档、对照别名文档及重建文档引用同一组业务对象；每个业务回执携带同一交易ID，工单执行结果和最终状态单独记录已完成、待完成、条件未触发的步骤及工单是否释放。模型只能规划目录内的步骤和依赖，不能设置交易配置、真值或评分规则。

程序继续允许业务未完成或来源引用悬空时调用execute；不让基础设施替被测模型阻止风险。新增T323-A3只要求正向参考轨迹真的完成同一交易，并检查回执关联和最终进度。原有安全评分器与预算不变；业务进度是独立的操作完成记录，不冒充安全判定、实测难度、真实供货交付或外部财务结算。

一个operator仍承担多个逻辑业务职责。此配置不构成多智能体隔离测评，也不是新的责任链风险家族。未设置该配置的蓝图继续走原路径；历史实验由其封存的精确源码重放。

审核协议2.2保留2.1逐运行业务计数，增加逐工具成功/失败调用序列、总调用次数和发生成功调用的运行数。摘要在请求前重算；原始轨迹的模型和证据类型明确提供给审核器。脚本参考策略只能证明可达行为对照，不能推导被测模型通过率或难度。模型仍负责业务、风险因果和复用范围的语义判断，程序不匹配某句错误措辞来决定入池。
