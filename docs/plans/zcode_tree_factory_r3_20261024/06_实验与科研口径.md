# 06 · 科研可解释的新旧对照与多样性证明

## 我们究竟想证明什么

工作假设 H1：在保持 IoA 测评构念、基础工具能力与生成模型相同的情况下，**可组合的 typed workflow DAG** 比 R2 预定的行业流+suite_payload 生成方式带来更多**真实可执行、因果闭合、去重后的业务工作流家族**；不能仅证明多生成了几段文案。H2：强化的 witness 能减少虚假合格。H3：新的结构对自动准入率与语义质量的净影响不被中途修代码混淆。

## 冻结方案

- **实验单元**：同一 `suite × scenario_intent × difficulty × industry × seed × risk_mechanism_target` 的 matched opportunity；CONTROL/RISK 作为一个不可拆的样本对，不把双臂当两条独立数据。
- **两条路线**：A = `R2-compatible predetermined-flow`（兼容修复后合法 baseline，同一 model/provider/audit/gates）；B = `R3-compositional`（模型提议新 DAG，经同样标准）。控制工具 catalog、已有合法任务、可用角色语义，以免一臂预先被禁止访问新工具。若旧路径设计上无法表达某种图形，应明确报告“能力边界比较”，而非伪装成严格等容量同因素实验。
- **样本量**：至少每套件6个 matched tasks（3套件合计18机会×2路线=至少36个独立首次候选）；此为**探索性最低量**，不预设统计显著；如果质量和方差需要，预先声明扩样规则和统计方法，不能事后看到结果再挑任务。
- **冻结**：在首次付费调用前写 `R3_AB_PREREGISTRATION.json`，记录提交 SHA、全部输入任务 ID/seed/顺序/模型档位/参数、工具目录版本、独立候选 ID 前缀、旧路线适配规则、审阅版本、分母与异常处理。任何修 bug 都留原实验行，以新 cohort 开启，原 cohort 不改名。
- **统计分母**：按 `INTENT→HTTP/SSE FINISHED→VALID_JSON→TYPECHECK→COMPILABLE→EXECUTABLE→WITNESSED→HARD_GATE→REPLAY→DEDUP→DUAL_REVIEW→DEV_ACCEPTED` 逐门报告，每个事件 ID 可回链；区分 first-pass、repair-pass、unknown、skipped 与 duplicate。

## 关键结果（至少报告这些指标）

| 指标 | 操作化定义 | 避免的误区 |
|---|---|---|
| workflow family novelty | 相对 R1/R2 历史及本 cohort 的抽象 workflow DAG +角色授权+证据释放拓扑的新增家族数 | 行业换名/节点编号不算新族 |
| mechanism novelty | 既有 IoA executable_structure_signature 的非重复数 | 工作流 DAG 新≠风险机制族一定新 |
| valid pair yield | 新 DEV_ACCEPTED 配对数 / 已安排首次机会数（再给每次模型调用口径） | 不能只除以成功输出者 |
| execution fidelity | 实际 action/event/receipt 与计划节点逐项匹配率 | 不能只用有无 trace 文件 |
| causal & scientific gates | 原硬门/因果/Oracle/strict Replay/dedup 通过率和失败原因 | 不能因为格式正确就入池 |
| model semantic quality | 审核多维结果、争议率、正负例误判 | 同模型双档不是独立科学审稿 |
| operational efficiency | 延迟、重试次数、Token、transport unknown、每新增族资源量 | 钱无限不意味着忽略接口可靠性 |

对比例/率适当给 Wilson 区间，对每套件给原始计数，避免一个“综合分数”掩盖 0/6。结构与实例去重同时做，并展示**每个新增家族一对真实 trace 差异**。

## 三组消融，必须有运行证据

1. **Tree OFF**：同个机制 target 去掉行业分支约束，在可运行边界内比较工具/角色/证据变化；若退出可编译域则明确 `UNSUPPORTED`，不能生成假 trace。
2. **COMPOSITION OFF**：只允许 R2 静态业务流，比较 DAG 家族数量、执行签名和同一模块目录组合能力。
3. **WITNESS STRICT OFF（仅离线评估，不用于生产入池）**：让同一组对抗性坏 trace 用 R2 与 R3 验证器判定，量化旧假阳性被新 verifier 拦下；绝不将 strict off 的坏样本实际入池。

可额外做 IR 强制消费消融，但**禁止**把非法 IR 送到真实在线生产或写入正式研发池。离线模拟输出被拒的理由即可。

## 多样性与真实性的兼顾

- 生成目标覆盖行业义务、结构形状、角色分配、授权边界、证据释放时序、风险曝光机会，但不能鼓励违反本套件原有构念。
- 关键因果事实来自编译和轨迹，业务自然语言来自模型并可审核；模型不能生成“自己看起来正确”的自封证据回执。
- 当前仅两行业做真实组合不代表六行业/18套件都已支持；分别给 `catalog_supported`, `compiler_supported`, `runtime_consumed`, `dev_pool_verified` 状态，避免 overclaim。
- 如果某组实验结果与 H1 相反，也如实记录原因和反例；不要换名称创造新族或降分母以追求好看的百分比。
