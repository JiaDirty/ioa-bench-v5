# IoA-Bench v5 唯一长期总 Goal：动态 IoA 测评平台、可复用高质量数据工厂、18项正式科学测评

## 最终使命

继续 `D:\Project\ioa_codex_spec` 的 **IoA-Bench v5** 项目。用现有18项构念契约、Suite、工具、参考策略、评分器及在线链路作为基线，逐步将其建设成：

1. **动态 IoA 执行环境**：可以依据经过验证的场景规范，自动建立不同拓扑、角色、权限、任务、证据、消息、状态、时序、工具与业务后果。Agent 在其获准且可观测的工具边界内自主选择行为、工具及次序；不是执行写死的 witness 路线。
2. **全局事件与科学测量系统**：不依赖特定操作顺序记录并关联所有受测行为、可见证据、消息传递、工具效果、授权变化和后果；以外部真值、事件记录和18个 Suite 的预注册判据，分别判断暴露/行动机会、安全、任务效用、恢复、不可判定和技术失败。保留CONTROL/RISK因果配对。
3. **自动高质量数据工厂**：MiMo-V2.6-Pro 创造结构不同且有效的场景 Blueprint；类型化编译器生成有状态的可执行世界与成对案例；确定性程序先进行科学与工程硬性 Gate、与既有数据做结构性去重；GLM-5.3-Flash 再独立复核语义、合理性和真实新颖性。失败拒收、原因追溯，不改变质量阈值凑数；支持18项各自的构念与能力。
4. **18项真正测评与科研交付**：在18项迁移、验证、独立专家审核、确认性 Pilot、科研冻结均满足预定验收后，使用冻结的 v5 环境、有效数据、统一模型协议测评官方唯一模型 `deepseek-v4.1-flash`；形成完整的执行记录、分母、统计不确定性、可复现实验及不夸大的科研结论。T361–T363始终标注 `SIMULATION_ONLY`。

**被测对象永远是模型在 IoA 任务中的内生安全性，不是评估 IoA 框架自身安全性。** IoA 世界是可配置、可信、受控的实验支架；其工程可靠性是测量有效性的前提，而非18项测评的研究对象。

## 关键科研不变量（任何阶段不可擅改）

- `contracts/v5/construct_maps.json` 为18项构念的正式依据；每项的操纵变量、对照约束、风险触发、反事实、外部真值、暴露/行动机会、安全及效用、恢复与排除条件均必须被保留或以正式科学决策版本化修改。不能借平台升级悄悄改测量目标。
- CONTROL 与 RISK 必须共享可比的基础世界及任务，只允许预注册的风险操纵变化；变化须有可程序检查的细粒度差分与机制检验。
- 模型、生成者和审核者都不能自证 Ground Truth；Oracle 必须来自版本化外部规范和确定性环境事实，不能由待测模型的结局反向决定。
- **Agent 自主选择合理路径**；参考 witness/naive/recovery 仅用于验证评分可辨识性，不得成为限制实际 Agent 行动或定义唯一正确路径的脚本。
- 所有外部动作有受控执行边界；原子记录“执行即留痕”，事件时序、调用方、授权链、状态前后、可见范围、原因和后果都可审计。不可观察的模型内部思考不得被宣称已被监测。
- 同时报告安全性和任务效用，区别真正拒绝危险、合理替代路径、过度拒绝、任务失败、超时/截断、评分弃权和环境故障。不能以模型是否不安全来选择或调参题目。
- 两个数据角色固定：AIHubMix `mimo-v2.6-pro`（生成）与 `glm-5.3-flash`（独立复核）；正式被测 `deepseek-v4.1-flash` 不参与生成/复核。具体配置以官方及网关核验事实为准，历史实验原样保存。
- 正式 DeepSeek 目前报告的协议为 v1.1.2、`max_tokens=131072`；最终以当前主线已锁定的实际协议、Provider 身份和验证证据为准，任何变更需版本化且不得事后按安全表现调节。
- 不覆盖既有2160条候选案例、历史4模型 Pilot、各次 Smoke、原始日志、PI 决策、长期 Goal 或旧版本证据。新数据始终有不同版本/命名空间，审核通过前只作为实验候选。
- Gate D 真实外部/领域独立审阅不能由 GLM 替代。Gate G 付费正式 Campaign 遵循既有单独 PI 授权与冻结要求；Goal 本身不等于已经解除所有授权门槛。

## 执行原则

- **一个项目、一条主线、一份权威 Goal、一套 Gate A–H**；当前 Goal 整合升级，不创建 v6、平行 Goal 或抛弃旧18 Suite。
- 优先复用现有运行引擎、工具、构念、调度、Score、Gate、Trace、数据构建和测试，按能力缺口最小扩展；科学意义明确时才加入新抽象，避免造一个无限通用的 DSL、重写18项或造复杂多层框架。
- 离线先行 → 最小真实探针 → 第一条全链路 → 小批扩展 → 分 Suite 渐进验证 → 外部审阅 → 确认性 Pilot → 冻结 → 经批准正式测量。
- 每次改动应有可复现失败案例、目标不变量、差异说明、测试与审计证据。确定性系统故障立即停止后续无效模型调用；反复质量失败则分析原因或报告能力缺口，不降低门槛。
- ZCode 自动承担普通工程设计/实现/回归，遇到构念、Oracle、评分语义、数据冻结、正式费用或外部审阅的关键科研决定时明确 `PI_DECISION_REQUIRED` 或 `BLOCKED_EXTERNAL_REVIEW`，不得假定用户已批准这些科学变更。

## 全局完成标准

`PLATFORM_READY`：动态 IoA 世界能支持真实自主多路径执行，事件账本可重放且可测量；至少跨不同构念的 Suite 有端到端证据，已扩展18项的能力和测试完备。

`DATA_FACTORY_READY`：全部18项有能力契约与适配器、规范化可执行 Candidate、结构性跨批去重、必要硬 Gate、独立语义验证、拒收追溯；抽样人工校验表明数据构念和评分合理，且有效场景家族达到预先论证的覆盖目标，不只是 JSON 合法/改行业名。

`MEASUREMENT_READY`：18项 Gate A–F 通过或具体阻塞明确；正式协议、数据、代码、分析计划、分母与种子已冻结并可复现。

`PUBLICATION_READY`：适用 Gate A–H 以原始证据通过；仅在实际有独立审核证据、获得必要 PI 正式运行授权、完成单模型18项正式实验和严谨统计后声明。任何缺失必须以证据支持的 `BLOCKED` / `PARTIAL` 状态呈现，不能宣称完美或科研完成。
