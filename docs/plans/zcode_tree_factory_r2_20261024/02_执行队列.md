# 直接推进的执行队列（M0–M6）

每个 M 包的状态只看**已改源码 + 可重跑命令 + 原始证据**。Agent 自主修普通工程问题，不需要向用户请求每一步确认；不另写长篇规划替代代码。不要覆盖旧冻结文件。

## M0｜快速基线（完成后直接开工）

- 确认当前 Git HEAD、dirty、writer lock、最新源码、真实 provider 路由、旧 `STOP.json` 和已知未知请求清单。新建 `artifacts/v5/data_factory/tree_factory_r2/<new_run_id>/`，绑定旧 `49d096e` 的历史快照而不是强行 checkout。
- 只生成一页 `BASELINE_R2.json` 和源码依赖路径，确认没有其他写者；不再给18项重新做大而全的历史调查。
- **出口**：可以确定 new-run 输出目录；历史无修改、旧请求不重发。

## M1｜修 IR 与树状业务真实消费（最优先）

1. 先复现外审两个 P0：切换医药/金融编译蓝图相同、非法 IR 绕过投影。把它们变成**先红后绿**测试。
2. 添加 typed `BusinessBinding` 与 `MechanismIR.validate() → Capability.validate() → blueprint_from_ir()` 强制主链。
3. 让 T331 有两条真实合成业务工作流（医药库存补货、金融支付清算）并由运行时实际消费；T321/T362 用同一绑定接口，至少每套件两条能力匹配分支。不能只做 T331 一次性特例，禁止复制出第二套执行 engine。
4. 复用现有6个执行机制因子，更新 canonical 机制/工作流签名和运行时见证。
5. **出口**：三套件离线完整 CONTROL/RISK + reference + replay 全绿；空 agent、图环、越权、跨域工具等在 IR 投影前失败；行业切换双世界真的不同。

## M2｜简化生成和审核交互（质量优先）

1. 新路线先生成/选择可执行能力规划和 IR，再在能力可用后才让模型生成较大文本；用程序拥有的真值，不让 LLM 编造评分。
2. 错误反馈仅带 failing field、capability ID、见证和期望约束；按 `FORMAT_FIXABLE / CAPABILITY_GAP / FIDELITY_FAIL / HISTORY_DUPLICATE / AUDIT_DISAGREEMENT` 分支直接处理。
3. 审核包改为精简事实摘要+保留源 SHA/JSON pointer 和按需证据片段；必须能在离线复现事实矛盾/引用造假；不要让模型先读重复的巨型原始 log。
4. 修 `audit_packet` 的固定16/32/64K白名单，使用 R2 合法大输出 profile；请求延长至任务适用值，不启用无限超时/无限修复。
5. **出口**：既有18负6正离线全绿+新持出样本；高/最大档真正审阅请求格式可验证；明细区分规则真值、模型分歧和审阅合同。

## M3｜真实 AIHubMix 和故障处理（尽快完成，不因费用省调用）

1. 从环境取凭据，使用用户指定模型 `deepseek-v4.1-flash-1017`。**仅在新的运行目录**做新唯一 receipt 小探针。旧坏 POST 和 STOP 原样封存；这次用户已授权开启全新的 R2 真实模型试点。
2. 校验 exact receipt、HTTP200、模型头/body、usage、支持的 `thinking/reasoning_effort/response_format/max_tokens`。请求合法上限以实时 schema 和返回码为准，能力声明中的393216不能当作已验证的账号可用值。
3. 保留已有 ModelPort/AIHubMixAdapter，SSE 流式聚合分离 reasoning/content。离线模拟长流、缺尾、已完成 finish=length、空正文、断线、header200后崩溃，准确分出 KNOWN_TRUNCATED / TERMINAL_FAILED / UNKNOWN。
4. 去掉费用软提醒/硬停和价格预留门槛；费用/usage仍如实记账。输出初始 131072，复杂 262144，经参数探针允许可升级393216，网关不接受就自动用已知合法上限；不要求每次强制输出很长。
5. **出口**：真实新探针精准 PASS 或外部障碍证据；参数配置完整写入 run contract；新请求 ID 的安全终态分类正确。若账号/网关仍不可用，先完成剩余离线任务，不把账户问题当架构无法修复。

## M4｜T321 优先拿第一对真实新数据

1. 先对封存失败的 T321 做**离线失败归因**（不复发旧请求）：合规字段缺失、high/max 意见分歧、版本不一致、world_delta_paths、早关闭门控；修程序可确定错误。
2. 只创建新的 T321 任务/候选 ID，优先挑**执行图新颖、行业流程可消费、历史去重安全**的机制。走 R2 真正的完整 Tree→IR→Compile→Execution→Audit 流程。
3. 若因模型完整终态 `finish=length` 失败，保留旧请求/结果，用新 ID 新最大输出预算生成；若 network UNKNOWN，不重发，隔离该候选继续其他无关新任务。
4. **出口**：至少1对全新 T321 `DEV_ACCEPTED`，其 IR/工具/业务事件/参考轨迹/两审核/去重/Replay均有证据。

## M5｜扩展到 T331/T362，并做最小公平对照

1. T331、T362 各至少1对 **新 R2** 研发接受，不把此前已有7对计入新产出。
2. 冻结每套件至少2个不同目标（建议3个），旧 `baseline_4stage` 和新 `tree_ir_runtime_v2` 尽量同一任务、相同模型、相同参数与质量门；两路线有不同调用阶段数时明确标注为“整套流程比较”，不可解释为单独 Tree 的效果。
3. 增补**离线四格消融**：无树无IR、仅树、仅IR、树+IR，分别测工具/角色/事件消费、非法输入拦截和签名；若希望线上科学归因，则另按等价阶段/提示冻结专项，不用本轮混淆设计硬做统计结论。
4. 产出 `WORKFLOW_DIVERSITY.csv`、`MECHANISM_DIVERSITY.csv`、`INSTANCE_YIELD.csv`、`AB_RESULTS.csv`、`FAILURE_FUNNEL.csv`，真正区分实例数量/业务图/执行机制数。记录 T362 两条已存实例结构重合的历史事实。
5. **出口**：三套件全都至少1对本轮新入池，18项可复用适配表明确剩余能力缺口；新增机制必须有运行见证。

## M6｜当前 HEAD 回归、交接

- 当前 HEAD `python -B -m pytest tests/v5 tests/m1 -q --junitxml=...`，保存 XML/实际命令/分母；每个新样本 strict Replay 和禁网 resume，旧历史保护验证。
- Git 本地 commit，不 push；保存修前/修后实际 diff，新终态 request ledger、参数实测、异常原始回执、GOAL 状态表、R2 报告/可读取池索引、两个打包 ZIP（源码 + 证据）。
- `GOAL.md` 中每项逐条给 PASS/FAIL/PARTIAL/BLOCKED/NOT_RUN，不准补写一份“想象中的已完成”报告。
- 确认 writer lock 释放、秘钥不出包；输出精确最后 HEAD 和源码 hash。

## 默认工程风格

一项改动对应一条可运行测试；不为所有假想异常加抽象层；先修消费关系再做复杂提示词；一次测试通后不反复清空结果重跑；不盲目抬高 max_tokens 到网关不接受的值；成功状态必须来自真实运行证据而不是代码存在。
